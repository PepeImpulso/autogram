# v1.22.2 — Bug-hunt fixes for the v1.22.1 car-speaker work

Pepe reported v1.22.1 didn't surface Autogram in his car's Android Auto
app menu. Code review found four real bugs and one perf issue that
could explain it. This release ships the fixes.

## What was broken in v1.22.1

1. **MediaBrowserService had no `android:icon` / `android:label`.**
   AA's app picker uses these to render the app tile; missing them
   can cause AA to skip the app entirely. (Existing CarAppService
   has both — copy-paste oversight on the new service.)
2. **MediaSession wasn't activated until first playback.**
   `setActive(true)` was deferred to `markPlaying`. Android Auto and
   Bluetooth car stereos that connect during an idle period would
   see the session as "not available" and may not list the app at
   all. Now activated immediately on session creation so AA can
   discover it on connect.
3. **`PlayReplyUseCase` listener registration ordering.**
   PlayReplyUseCase's init block registers itself as the
   MediaSessionCompat callback listener. But Hilt singletons are
   constructed lazily — if AA bound the MediaBrowserService before
   anything else triggered PlayReplyUseCase, AA's transport taps
   (Play / Pause / PlayFromMediaId) would log "before listener
   attached" and silently drop. Fixed by injecting
   PlayReplyUseCase into AutogramMediaBrowserService so the
   constructor runs (and registers the listener) before the
   browser is bound by AA.
4. **Browser catalog used `getPinned()` for conversation lookup.**
   Messages from non-pinned (archived / past-target) conversations
   showed "Autogram" instead of the actual contact name in AA's
   catalog. Switched to `getAll()`.
5. **`pendingChildren` loaded every message in the DB** then
   filtered in-memory by `state == PENDING_PLAYBACK`. Heavy on a
   user with thousands of messages. Switched to the canonical
   `observePendingPlaybackQueue()` flow's first emission — same
   data the Pending tab uses, ordered the same way.

## Test fix

`PlayReplyUseCaseTest` had been broken since v1.22.0 (missing
`audioRecorder` mock added in the recording-vs-autoplay collision
fix) and got worse in v1.22.1 (missing `conversationRepository` +
`mediaPlayback`). Tests now compile and pass.

## After installing v1.22.2 on the Galaxy

If Autogram still doesn't appear in Android Auto's media tab:

1. **Disconnect + reconnect AA.** AA caches the app list on connect;
   it won't pick up newly-installed media apps until the next
   bind cycle.
2. **Enable AA developer mode + "Unknown sources".** Sideloaded
   media apps (anything not on Google Play) need this. To enable:
     a. Open Settings → Apps → Android Auto.
     b. Tap "Version" 10 times to enable Developer Mode.
     c. In AA's 3-dot menu, open Developer Settings.
     d. Enable "Unknown sources".
   Autogram's existing CarAppService might have worked without this
   for templated apps; MediaBrowserService for sideloaded apps is
   stricter.
3. **Reboot the phone** (clears AA's stale state).

If after all three steps Autogram still doesn't show up, ping back
with One UI version + AA version + car make/model — there are
known carfirmware-specific quirks we'd need to dig into.
