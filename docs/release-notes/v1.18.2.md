# v1.18.2 — Add the second AA permission: ACCESS_SURFACE 🔑

v1.18.1 added `NAVIGATION_TEMPLATES` so `NavigationTemplate` would
render. But `AppManager.setSurfaceCallback()` needs a **second**
signature-protected permission, `androidx.car.app.ACCESS_SURFACE`,
which I missed. logcat caught it:

```
W/CarApp.H.Tem: App [com.autogram.app/AutogramCarAppService]
  trying to access surface when the permission was not granted
W/CarApp.H.Tem: java.lang.SecurityException: The car app does
  not have a required permission: androidx.car.app.ACCESS_SURFACE
  at gxp.setSurfaceCallback(SourceFile:11)
```

Without `ACCESS_SURFACE`, Gearhead accepted the NavigationTemplate
but refused to hand us the raw Surface, so our custom canvas
renderer never drew anything — the AA screen went blank and the
host popped the generic "Autogram ha detectado un error no
esperado" dialog.

## 🐛 Fixed

- Added `<uses-permission android:name="androidx.car.app.ACCESS_SURFACE" />`
  to the manifest.

## Install

Update from 1.18.1. Open AA, tap Autogram — the custom canvas
(big Merlin + chips + secondaries row) should finally render.
If the error dialog still appears, reconnect AA or toggle
"Unknown sources" off+on once in Android Auto → Developer
Settings so Gearhead re-evaluates our permission set.
