# v1.18.7 — TDLib now starts when launched from Android Auto 🔌

In the DHU the user tapped Merlin, saw the red recording ring,
spoke, tapped again to send — and nothing showed up in Telegram.
Logcat tells the story:

```
04-23 00:04:09 libtdjni.so loaded
04-23 00:06:10 MediaRecorder start  (tap Merlin)
04-23 00:06:14 MediaRecorder stop   (tap to send)
04-23 00:06:15 MediaMetadataRetriever (duration extraction)
(… nothing …)
```

No `DLTD` (TDLib) log lines at all from the Autogram process.
The native library was loaded, but no TDLib client ever
authenticated. The recording was captured, validated, the send
use case ran, `authState.value` was `!= Ready`, so
`persistQueuedOffline` fired and the message went into the
outbox with no sender to drain it.

## 🐛 Root cause

`MtprotoReceiverService` — the foreground service that owns the
TDLib session — was only ever started from
`MainActivity.onCreate()`. When the user launches Autogram
directly via the Android Auto tile, MainActivity isn't created,
so the service never starts, TDLib never authenticates, and
every recorded message queues forever.

## 🐛 Fixed

Added a `startForegroundService(MtprotoReceiverService)` call in
**`AutogramCarAppService.onCreate()`**, wrapped in `runCatching`
and idempotent (if MainActivity already started the service, the
second intent is a no-op). Now TDLib comes up whether the user
enters via the phone app or the car.

## Install

Update from 1.18.6. Reinstall, force-stop Autogram once so the
CarAppService gets re-created, then tap Merlin in AA:
record → tap → Telegram should show the voice note arriving.
