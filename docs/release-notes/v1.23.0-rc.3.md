# v1.23.0-rc.3 — Phase 5 voice commands (action commands only)

Pre-release supersedes rc.2. Phase 1 (manifest registration) and
Phase 2 (voice loop) carry over unchanged. **New in rc.3: hands-free
action commands.** When you record into the assistant and your speech
matches a known control keyword, the action runs and the recording is
discarded — no junk voice note ends up in Merlín's chat.

## What's new

When you tap mic, speak, and tap stop, the assistant now:

1. Stops the recorder.
2. Transcribes the audio locally (on-device, offline-capable when the
   language pack is installed).
3. Parses the transcript for command keywords.
4. **If a command matched** → runs the action, discards the audio,
   shows a brief "Done · <action>" confirmation, and closes.
5. **Otherwise** → falls back to sending the recording as a voice note
   to your selected target (default: Merlín). Same behavior as rc.2.

## Recognized commands (English + Spanish)

| Action | English phrasings | Spanish phrasings |
|---|---|---|
| **Play pending** | "play pending", "play queue", "drain queue", "play all" | "reproducir pendientes", "reproducir cola", "lee pendientes" |
| **Repeat last** | "repeat", "replay", "repeat last", "play last (one)", "replay the last message" | "repite", "repetir", "repítelo", "repite el último", "vuelve a reproducir" |
| **Pause** | "pause", "pause it", "pause playback" | "pausa", "pausa la reproducción", "espera" |
| **Resume** | "resume", "continue" | "reanuda", "continúa", "sigue", "continuar" |
| **Stop** | "stop", "stop playback", "stop playing", "stop it" | "para", "detener", "detente", "alto", "para la reproducción" |

Patterns are full-utterance matches — saying "play pending please" or
"please pause" today won't match (intentional: tighter precision is
better than broader recall for v1, since false-positives mean a
recording gets *silently discarded*). Easy to widen in rc.4 once the
real-world transcripts are reviewed.

## Internal

- **`AssistantCommandParser`** — new object in
  `app/src/main/java/com/autogram/app/ui/assistant/`. Pure utility,
  zero dependencies, deterministic. Unit-testable.
- **`SendVoiceMtprotoUseCase.stopWithoutSending()`** — new entry point
  that stops the recorder and returns the audio file without
  triggering the send pipeline. Lets the assistant inspect the
  recording before deciding.
- **`AssistantViewModel`** state machine grew two states:
  `Transcribing` (visible while the on-device engine works,
  ~1–3 s typically) and `ActionExecuted(command)` (1.2 s confirmation
  before close).
- **`AndroidOnDeviceTranscriptionEngine`** is reused unchanged —
  same engine that already powers History bubble transcriptions.
- 9 new localized strings across all 6 UI locales.

## Verification on the Galaxy

1. Pull rc.3 via in-app updater.
2. Trigger assistant gesture → tap mic → say **"repite el último"** → tap stop.
3. Verify: brief "Listening for commands…" → "Done · Repitiendo último"
   → activity closes → the most recent incoming voice plays via the
   normal autoplay path.
4. Repeat with **"reproducir pendientes"** → expect "Done · Reproduciendo
   pendientes" → the pending queue starts draining.
5. Sanity: tap mic → say something that's NOT a command (e.g., "hola
   Merlín") → tap stop → verify the recording is sent to Merlín as a
   normal voice note (rc.2 behavior preserved).
