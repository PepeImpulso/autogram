# v1.24.4 — Stale Now Playing panel + dead Play button 👻▶️

Fix for the "ghost waveform" Pepe hit in the Pending Queue: empty list,
yet a Now Playing panel pinned at the bottom showing his main contact,
and tapping its Play button did nothing the first time.

## 🔧 Fixed

- **Stale `PLAYING` / `PAUSED` rows survived process death.** The Now
  Playing panel's source-of-truth is a Room query —
  `SELECT * FROM messages WHERE state = 'PLAYING' OR state = 'PAUSED'`.
  When playback was interrupted by anything that didn't run the normal
  `markStopped()` chain (process kill, MediaPlayer crash, OOM trim),
  the row stayed in those states forever. On next launch
  `observeNowPlaying()` returned it, the panel rendered, and the user
  saw "now playing" UI for a session that no longer existed. v1.24.4
  sweeps those rows in `PlayReplyUseCase.restorePendingQueue()` at
  app start and demotes them to `PLAYED`.

- **Play button on the Now Playing panel was a no-op when the row
  was stale.** Tapping Play called `playReplyUseCase.resume()` →
  `audioPlayer.resume()` → `mediaPlayer?.let { it.start() }`. After a
  process restart `mediaPlayer` is null, so the safe-call body never
  executed and nothing happened. v1.24.4 introduces
  `playOrResumeNowPlaying()` in the Pending Queue ViewModel that
  picks the right action based on `PlaybackStatus`:
  - `Paused` → `resume()` (live MediaPlayer or TTS waiting).
  - `Playing` → no-op (button is showing Pause anyway).
  - `Idle` / anything else → `playFromHere(message)` (fresh start).
  Now a tap always produces audio when the panel is visible.

## 🛠️ Internal

- New `MessageDao.getStaleNowPlaying()` one-shot suspend query +
  `MessageRepository.getStaleNowPlaying()` seam. Same WHERE clause as
  the existing `observeNowPlaying()` Flow but without the `LIMIT 1`,
  so the startup sweep catches every stuck row instead of one at a
  time.
- `PendingQueueViewModel.playOrResumeNowPlaying()` branches over
  `playReplyUseCase.playbackStatus.value` to choose between `resume`
  and `playFromHere`. The Now Playing panel's `onResume` callback is
  wired through this new method.
