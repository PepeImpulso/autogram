# v1.16.0 — Auditoría a fondo + hardening + docs completas 🔍📋

Cierre del sprint post-roadmap. Tres pasadas de auditoría
(testing coverage, re-auditoría de bugs, third-pass con foco en
seguridad/i18n/accesibilidad) + documentación retroactiva de las
25 releases anteriores.

## 🐛 Fixed (crítico/alto)

- **Overflow de `Long → Int` en `PinnedPickerViewModel`**: el
  casteo `.toInt()` de un `forumTopicId` de 64 bits podía
  truncar sin aviso en chats con IDs altos. Reemplazado por
  `asInt32OrNull()` helper, que loguea + devuelve null si no
  encaja. 2 sitios corregidos.
- **`state.error!!` en dos pickers** (TargetPicker, PinnedPicker):
  cuando el `error` era null pero el flow llegaba al branch de
  error, crasheaba con NPE. Cambiado a `state.error ?:
  stringResource(...)`.
- **Regex de `scrubPii` comía espacios trailing y matcheaba IDs
  puros de dígitos**: fix de orden (LONG_ID primero) + patrón
  más estricto (phone requiere `+` prefix o grupos de
  separadores). 11 tests MockK que descubrieron los bugs.
- **WorkManager crash en unit tests**: `RetryWorker.enqueueOnce()`
  asumía que WorkManager estaba inicializado; envuelto en
  `runCatching` con fallback `Timber.w`, no fatal porque el
  worker tiene su propio schedule.

## 🐛 Fixed (medio)

- **Activity labels hardcoded en español** en el `AndroidManifest`
  (`ManagePinnedActivity`, `PinnedPickerActivity`,
  `QuickRepliesSettingsActivity`). Reemplazados por referencias
  a strings.xml — ahora se traducen en los 6 idiomas igual que
  el resto de la UI.
- **Límite de tamaño de backup en import**: un `.autogram`
  hostil >100 MB podía OOM-ear el import (plaintext +
  BackupPayload + base64 en heap simultáneamente). Rechaza
  ficheros >50 MB como `Corrupt` antes de intentar descifrar.
- **Validación de endpoint LLM**: `Request.Builder().url()` con
  URL malformada tiraba `IllegalArgumentException` y crasheaba
  el summarize/suggest path. Ahora se valida scheme (`http`/
  `https`) y parse con `toHttpUrlOrNull()` antes — fallo
  silencioso a "NotAvailable" / fallback a regex.
- **Auto-clear de `selectedFolderId`**: cuando el usuario
  borraba la carpeta activa, el tab filter se quedaba apuntando
  a un ID inexistente → el grid aparecía vacío aunque hubiera
  círculos. Ahora se detecta y se clearea a "Todas" automático.
- **`CircleFolderDao.detachAndDelete`** promocionado a
  `@Transaction` para que "limpiar folderId de conversaciones
  + borrar folder" sea atómico — antes un crash entre ambas
  dejaba conversaciones apuntando a una carpeta borrada.

  aplicarlo como cuerpo del release. Acepta también `--notes

  "qué cambió" de cualquier versión del historial desde la UI
