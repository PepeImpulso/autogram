# v1.19.11 — Eleventh audit: photo file leak on unpin-topic 🧹

Eleventh hostile audit pass. One real (minor) finding: unpinning a
forum topic from the multi-select picker leaked its user-picked
photo file to disk. Fixed. Everything else checked clean.

## 🐛 Fixed

### `PinnedPickerViewModel.confirmSelectedTopics` didn't drop photo files on unpin

`ManagePinnedActivity`'s `remove()` cleans up `photoLocalPath`
before calling `conversationRepository.delete(...)`:

```kotlin
conv.photoLocalPath?.let { runCatching { File(it).delete() } }
conversationRepository.delete(id)
```

The symmetric path in `PinnedPickerViewModel.confirmSelectedTopics`
(unpinning one or more topics via the forum multi-select) was
missing the photo delete. So whenever a user had set a custom
photo on a pinned topic and then unpinned it, the row's cascade
deletion took the messages but the image file stayed behind in
`filesDir/circle_photos/` forever — retention's orphan sweep
only covers `audio_incoming / audio_outbox / audio_outgoing`, not
circle photos. Added the same photo-delete line on the unpin path.
