# v1.24.1 — TTS audio focus + AA reply discoverability 🔊✉️

Follow-up to v1.24.0 after testing in a real Seat Ateca: the audio
"fix" didn't land because the actual failure path was TTS, not file
playback. v1.24.1 patches the real root cause and makes the AA reply
controls reachable.

## 🔧 Fixed

- **TTS now requests audio focus.** `TtsPlayer.speak()` always set
  `AudioAttributes(USAGE_MEDIA / CONTENT_TYPE_SPEECH)` but **never**
  called `AudioManager.requestAudioFocus()`. `AudioPlayer` has always
  requested focus for file playback, so the symmetry hid the gap: when
  an incoming message is summarised or text-only it goes through
  `playSummaryOrTranscription` → `TtsPlayer.speak()`, and on Android
  Auto the host's audio policy silently drops unfocussed
  `USAGE_MEDIA` TTS from background services. The "Last playback
  route" diagnostic in v1.24.0 stayed empty because `AudioPlayer`
  never ran — the path that ran (`TtsPlayer`) didn't update it.
  v1.24.1 ports `AudioPlayer`'s focus-request code into `TtsPlayer`
  with per-utterance acquire/release, honouring the same
  `AudioFocusMode` setting (Transient+Duck / Transient / Gain).
  Denial logs a warning but keeps speaking (consistent with
  `AudioPlayer`), so a stricter mode can still reach the speakers.

- **Reply control on the Inbox tab.** Every conversation row on the
  Inbox tab now has an explicit "Reply" Action alongside "Record".
  Tap → pushes a child Screen listing all enabled quick replies plus
  a "Record voice reply" row, all pinned to that conversation. AA's
  host on Seat Ateca's latest model never renders the implicit reply
  input attached to `ConversationCallback.onTextReply`, so the reply
  UX was invisible there. This screen makes the reply path
  explicit, regardless of host quirks.

## ✨ Added

- **Richer "Last playback" diagnostic.** The phone Settings → AA
  audio routing card no longer shows just the routed device. It now
  shows source (AudioPlayer / TTS) + focus result (granted / denied)
  + routed device label + focus mode used + timestamp. A line like
  `TTS · Bus (AA media stream) · focus=granted · mode=TRANSIENT_MAY_DUCK
  · 14:23:01` is enough to tell whether the issue is "playback didn't
  start", "focus was denied", or "audio went to the phone speaker
  instead of the car". Source feed is a shared `PlaybackDiagnostics`
  singleton both players write to.

- **MessagingStyle audio Uri.** Incoming voice notifications now
  carry the audio file Uri via `MessagingStyle.Message.setData(
  "audio/ogg", uri)`, exposed through the existing FileProvider.
  Defence in depth: if our in-app playback gets muted by a particular
  AA host's audio policy, AA's notification reader can play the
  voice through the car speakers itself. The notifier falls back to
  text-only `MessagingStyle.Message` when FileProvider can't expose
  the path (e.g. unexpected TDLib storage layout).

## 🔍 Changed

- **Removed from AA's Media tab.** `automotive_app_desc.xml` no
  longer declares `<uses name="media"/>`. Autogram now only appears
  in AA's Apps / Communication section, which is where the
  TabTemplate (Inbox / Shortcuts / Pending / Settings) lives. The
  Media tab had been dual-listing Autogram alongside Spotify, and
  users (Pepe) kept landing there expecting the full app and finding
  only the browseable catalog. `MediaSessionCompat` itself stays
  active under the hood — Bluetooth transport, lock-screen Now
  Playing, and AA's audio routing all key off the session token,
  not the descriptor.

## 🛠️ Internal

- **`PlaybackDiagnostics` singleton** at
  `app/src/main/java/com/autogram/app/infrastructure/audio/PlaybackDiagnostics.kt`.
  Both `AudioPlayer` and `TtsPlayer` write a `PlaybackAttempt` on
  every play start; `SettingsViewModel` collects the StateFlow for
  the diagnostics card. Replaces the v1.24.0 `AudioPlayer.lastRoutedDeviceType`.
- **`ConversationReplyScreen`** at
  `app/src/main/java/com/autogram/app/ui/auto/ConversationReplyScreen.kt`.
  Child Screen pushed by the per-row Reply Action on the Inbox tab.
- **FileProvider paths extended** in
  `app/src/main/res/xml/file_provider_paths.xml` to cover TDLib's
  `filesDir/tdlib/files/` subtree so the audio Uri resolves.

## Install

In-app updater. Stable channel.

## Migration notes

No schema change (no Room migration). The v1.24.0 settings remain;
the new behaviour applies automatically.

After upgrading, **on Android Auto open Autogram from the Apps /
Communication section** (not the Media tab — Autogram no longer
appears there). You'll land on the TabTemplate with the four tabs.
Tap a conversation row in Inbox → "Reply" Action appears next to
"Record".
