# v1.23.6 — Security hardening + queue navigation + shortcut targeting 🛡️⏯️📌

Three usability features and a defensive sweep of the security posture
covered in issue [#69](https://github.com/PepeImpulso/autogram/issues/69).

## ✨ Added

- **Pending Queue · Skip Previous + Mark all as listened.** The Now Playing
  panel's left-arrow button now jumps to the previous-played message
  (history depth = 5) instead of just restarting the current one. Disabled
  when nothing has played yet, so the affordance never lies. Added a
  "Mark all as listened" button at the top of the queue with a confirm
  dialog — bulk-acknowledges every pending row without playback when the
  user wants to clear a backlog.
- **Shortcut · Per-contact targeting.** Each text/voice shortcut can now be
  pinned to a specific pinned circle through a "Send to" picker in the
  shortcut editor. A pinned shortcut always sends to that contact, even when
  another circle is the on-screen primary. Default ("Active circle")
  preserves the legacy behaviour for existing shortcuts.

## 🐛 Fixed

- **TtsPlayer · Speech rate now sticks across `stop()`.** Some TTS engines
  reset speech state on `stop()`, so the rate set before the stop call was
  silently dropped. `setSpeechRate(playbackSpeed)` now runs immediately
  before each `speak()` so the user's playback-speed setting also applies
  to text messages read aloud (previously only audio messages respected
  it).

## 🛡️ Security (issue #69)

Defensive sweep over the still-applicable findings of the static audit. The
findings naming `TelegramApiClient.kt`, `AutogramPollingService.kt`, and
`SendMessageUseCase.kt` were already obsolete — those files were deleted in
the MTProto migration.

- **`ConversationEntity.botToken` dropped from Room.** The column was dead
  code (set to "" for new rows since the MTProto switch) but pre-MTProto
  rows could still hold a real token in plaintext. Migration `v17 → v18`
  uses the SQLite recreate-dance to remove the column; entity, domain
  model, mappers and call sites updated to match. Forensic-level token
  recovery from local DB is no longer possible.
- **HTTP logging path tightened.** `HttpLoggingInterceptor` removed
  entirely (it ran before any redactor, so it would have logged the
  unredacted URL). Replaced with a single debug-only logging interceptor
  that redacts bot-token URL segments AND common sensitive query params
  (`api_key`, `token`, `Authorization`, `secret`, `signature`, …) before
  ever calling `Timber.d`. Release builds add zero HTTP logging; the
  `okhttp-logging` dep was removed from the build entirely.
- **PII removed from `Timber` log statements.** `AudioRecorder` /
  `AudioPlayer` / `QuickRepliesSettings` no longer log absolute paths
  (just filenames now). All Spanish log messages translated to English so
  Sentry / logcat output is uniform per the project's logging convention.
- **`READ_PHONE_STATE` graceful degradation verified.** Permission is
  requested at runtime in `MainActivity.requestCompanionRuntimePermissions`;
  `CallStateMonitor.start()` checks again before listening and bails
  silently if denied. Result: in-call auto-pause is disabled but the rest
  of the app keeps working.
- **Settings input validation hardened.** `summaryLlmEndpoint` is trimmed,
  control characters stripped, scheme normalised to `https://` when the
  user pasted a host without one, and capped at 2048 chars.
  `summaryLlmApiKey` trims, strips control chars, and caps at 4096 chars
  (prevents Authorization-header-corruption from stray newlines and
  bounded-DoS from huge keys). `summaryLlmModel` capped at 128.
  `languageTag` validated against a conservative BCP-47 regex before
  reaching `LocaleListCompat.forLanguageTags`.

### Out of scope (filed for v1.24+)

- Full DB encryption (SQLCipher integration) — substantial migration;
  retention + autoDelete already cover most of the day-to-day exposure.
- Gradle dependency verification + Renovate/Dependabot — CI infra change.
- Findings 3 and parts of 4 / 6 from the audit refer to files deleted in
  the MTProto migration — there is nothing left to fix.

## Migration notes

Room schema bumped to v19 with two explicit migrations. Existing user data
survives the upgrade — botTokens (mostly empty strings) are dropped, and
quick_replies gets a new nullable `targetConversationId` column that
defaults to NULL for every existing row, preserving today's "send to
primary" behaviour until the user pins a shortcut to a specific circle.
