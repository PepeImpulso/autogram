# v1.20.19 — Auto-play falls back to original audio when transcribe fails

A second auto-play bug surfaced after v1.20.18. Same symptom as before
("auto-play is on but no sound comes out") but a different root cause,
visible when the device doesn't have on-device speech recognition for
the user's locale.

## Fixed

- **Voice replies disappeared into a silent skip when summarize was on
  and on-device transcription wasn't available.** With `Summarize long
  messages = ON` and an engine selected, the receiver waited for
  transcription to finish before TTS-ing the summary. If the transcribe
  engine returned `NotInstalled` / `LanguageUnavailable` (no on-device
  recognizer for the locale, or no Google speech services on the
  device), no transcription was written. `playSummaryOrTranscription`
  then saw `summary == null && transcription == null && textContent ==
  null` and returned silently — no playback, no queue, no error
  surfaced. The user only saw the per-circle "1" badge update, with
  nothing actually playing. `playSummaryOrTranscription` now falls back
  to the original audio when there's no readable text but the message
  has an audio file. Functional behaviour is now: TTS the summary if
  the engines produced one, otherwise TTS the raw transcription,
  otherwise play the original `.ogg`. The user always hears something.
