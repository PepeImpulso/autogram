# v1.24.2 — Audio routing rollback + in-app debug logs 🔁📋

Hotfix for v1.24.1. The "remove `<uses name="media"/>`" change was the
wrong trade-off — it broke audio routing for any playback path that
goes through `PlayReplyUseCase` (which is most of them) and also broke
how Pepe finds Autogram on Android Auto. Restoring the capability, plus
adding the debug-log feature you asked for.

## 🔧 Fixed

- **Audio routing for in-app playback.** v1.24.1's diagnostic showed
  `AudioPlayer · unknown · focus=granted` on a failed in-car replay —
  i.e., the OS granted us audio focus but had no output device to
  route it to. That's the exact symptom v1.22.1 originally fixed by
  declaring `<uses name="media"/>` in `automotive_app_desc.xml`:
  without it, AA stops observing our `MediaSessionCompat` and the
  OS-level "where do I route this `USAGE_MEDIA` audio" query returns
  null. Settings → Test Playback kept working because the foreground
  phone Activity has its own audio authorisation, but
  `PlayReplyUseCase.markMediaSessionPlaying()` → `AudioPlayer.play()`
  from any other context fell into the AA-doesn't-know-us bucket and
  the audio went nowhere. v1.24.2 restores the capability.

- **AA car-screen "regression".** With `<uses name="media"/>` gone,
  Autogram disappeared from AA's Media tab. When Pepe couldn't find
  it on the car screen, AA fell back to its built-in "No messages
  received while driving" notification reader — which is the system's
  surface, not Autogram. Restoring the media capability brings the
  Autogram tile back to the Media tab as the familiar entry point.

## ✨ Added

- **In-app debug logs.** New Settings → "Debug logs" card with two
  buttons: **Send debug logs** (shares an export of the rolling log
  file via the system share sheet — email, Telegram, anything that
  accepts `text/plain`) and **Clear debug logs** (wipe before
  reproducing a bug for a clean capture). A new `FileLoggingTree` is
  planted in `AutogramApplication.onCreate()` alongside the existing
  release tree, so every Timber event is appended to a rolling file
  at `cacheDir/autogram-logs/autogram.log` (rotates at 1 MB, two
  files retained — 2 MB worst-case footprint). Works in release
  builds; no adb / Sentry required. Send these when reporting issues
  and the developer can read the full runtime trace.

## 🔍 Changed

- The discoverability problem v1.24.1 tried to solve (users landing on
  the Media tab and finding only a browseable catalog) is real but
  the fix has to come from somewhere else — not at the cost of audio
  routing. Tracked for a follow-up: enrich the Media tab catalog with
  a clear "Open Autogram from Apps for full reply UX" item, instead
  of removing Autogram from the tab entirely.

## 🛠️ Internal

- `FileLoggingTree` at
  `app/src/main/java/com/autogram/app/infrastructure/platform/FileLoggingTree.kt`.
  `synchronized` lock on every write since Timber events come from
  arbitrary threads; cap is hardcoded at 1 MB × 2 slots; export
  materialises a third file under cacheDir that the FileProvider can
  expose to the share intent. Cleared via the Settings button or by
  Android's normal cache-cleanup pressure.

## Migration notes

No schema change. After upgrading, in Android Auto Autogram appears
**both** in the Media tab and in the Apps / Communication section.
For the new 4-tab UI (Inbox / Shortcuts / Pending / Settings) and the
explicit Reply button, open from the Apps section. For the simpler
browse-and-listen-back surface, open from the Media tab. Audio
routing should now work from both surfaces.

If anything still doesn't behave: phone Settings → Debug logs → Send
debug logs. The log file captures every Timber event from app start.
