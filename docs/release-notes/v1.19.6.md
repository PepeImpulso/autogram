# v1.19.6 — Seventh audit: fix silent drop of AA voice notes when preview-before-send is on 🚗🎙️

Seventh hostile audit found one real user-visible bug: voice notes
recorded in Android Auto could be silently parked (never sent) if
the user had enabled **preview-before-send** in the phone's
settings. Fixed.

## 🐛 Fixed

### AA `stopAndSend` gets stuck on `PreviewReady` when preview-before-send is on

`SendVoiceMtprotoUseCase.stopAndSend()` honours the phone's
`previewBeforeSend` setting by parking the recorded file and
switching to `SendStatus.PreviewReady`. The phone UI reacts to
that state by opening a preview sheet with **Play / Send / Discard**
buttons. The AA `MainScreen`, however, does **not** handle
`PreviewReady` in `onGetTemplate()` — it falls through to the
`else` branch and re-draws the home template. Net result:

1. Driver taps Merlin on the car screen, records a voice note, taps
   to stop.
2. `stopAndSend()` sees `previewBeforeSend=true`, parks the file in
   `previewFile`, and emits `PreviewReady(durationMs)`.
3. AA surface redraws the home screen — no banner, no preview
   sheet, no indication the message didn't ship.
4. Driver assumes it was sent, drives off. The voice note sits in
   `previewFile` forever (no AA UI to confirm or cancel), until
   the user opens the phone app.

Added a `skipPreview: Boolean = false` parameter to
`stopAndSend()`. AA's `MainScreen.stopAndSend` now passes `true`:
the car is a preview-less context by design (no sheet surface to
confirm on, and presenting one would be a distraction UX anyway).
Phone UI keeps the default (`false`) so the phone preview flow is
unchanged. Voice-command `ENVIAR` from AA goes through the same
AA `stopAndSend` wrapper, so voice sends also skip preview.

Single surgical change: one new parameter, one updated call site,
one gate on `if (!skipPreview && settingsRepository.get()...`.
