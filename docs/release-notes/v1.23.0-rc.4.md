# v1.23.0-rc.4 — Phase 1b: actually wire Samsung's assistant gesture

**Direct fix for the rc.1-3 blocker** Pepe hit on the Galaxy: Autogram
showed up in Settings → Default digital assistant app and was
selectable, but pressing the assistant gesture still routed to
Google. This release unblocks that.

## Why it wasn't working before

Declaring the `ACTION_ASSIST` intent-filter on `AssistantActivity` is
enough to *list* an app in Samsung's "Default digital assistant app"
picker, but the OS gesture trigger (long-press home, side-key, etc.)
binds to a separate hook called `VoiceInteractionService`. Apps
without a `VoiceInteractionService` get listed but never invoked —
the gesture falls through to whichever app does have one (Google by
default).

## What rc.4 ships

- **`AutogramVoiceInteractionService`** — the OS bind point. Thin
  shell, just announces "Autogram is the active assistant" on
  `onReady()`.
- **`AutogramVoiceInteractionSessionService`** — spawns a session
  when the gesture fires.
- **`AutogramVoiceInteractionSession`** — when the OS calls
  `onShow()`, it immediately launches `AssistantActivity` and hides
  the session. So the gesture flow is: OS gesture → OS binds our
  session service → session launches AssistantActivity → existing
  Phase 2 / Phase 5 voice loop runs.
- **`res/xml/assistant_metadata.xml`** — the `<voice-interaction-
  service>` declaration the OS reads when Autogram is selected as
  the default assistant. Points to the session service and asserts
  `supportsAssist=true` plus `supportsLaunchVoiceAssistFromKeyguard=
  true` so the gesture works even from the lock screen.
- **Manifest** — both services declared with
  `android:permission="android.permission.BIND_VOICE_INTERACTION"`
  (system-only permission, prevents impersonation), exported, with
  the `android.service.voice.VoiceInteractionService` intent-filter
  on the main service.

## What you need to do on the phone after install

You should already have Autogram selected in Settings → Default
digital assistant app from rc.1. After installing rc.4:

1. Pull rc.4 via in-app updater.
2. **Re-select Autogram** in Settings → Default digital assistant app
   (Android sometimes drops the role binding when a new
   `VoiceInteractionService` registers — the picker may need a fresh
   tap to rebind).
3. Trigger the gesture (long-press home / side-key / whatever you
   normally use to invoke the assistant).
4. AssistantActivity should now open instead of Google.

## What this build does NOT change

- Phase 2 voice loop, contact picker, and Phase 5 action commands
  carry forward verbatim from rc.3. No flow changes inside
  AssistantActivity.
- No on-device speech recognition shipped here. Phase 5 still uses
  the existing `AndroidOnDeviceTranscriptionEngine` after the user
  taps stop. Future Phase 5b could drive transcription live during
  the OS-managed listening surface, but that's out of scope.
