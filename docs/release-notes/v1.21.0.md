# v1.21.0 — Unified Pending + History, portrait lock, clearer Settings

Three open issues resolved in one release. The old Pending Queue lived
behind a banner that vanished as soon as you drained it, leaving the
screen unreachable. We've folded it into History as a tab so it's
always one tap away. Plus the app no longer rotates into a half-broken
landscape layout, and the Settings entry that configures home-screen
contacts no longer collides with the home-screen Shortcuts feature.

## Added

- **Pending tab inside History.** History is now a two-tab screen with
  Pending and History tabs sharing the same back arrow and title. The
  "▶ N pending" banner on Home opens the Pending tab directly; opening
  History from the navbar or a per-circle badge defaults to the
  History tab. The Pending tab is always reachable via tab switch even
  when no banner is showing on Home — fixing the long-standing
  dead-end where users couldn't revisit the queue once it was empty
  on Home. Playback state is shared via the existing singleton
  `PlayReplyUseCase`, so starting a message in one tab and switching
  to the other never interrupts audio.

## Changed

- **Settings · "Manage shortcuts" → "Home contacts"** (issue #65). The
  Settings row that picks which contact circles appear on the home
  screen used to be labeled "Manage shortcuts", colliding with the
  separate "Shortcuts" feature on the home navbar (which manages quick
  replies). The label now reads "Home contacts" / "Contactos del
  inicio" / "Contacts d'accueil" / "Startbildschirm-Kontakte" /
  "主屏联系人" / "ホーム連絡先". The underlying resource key
  (`settings_manage_pinned`) is unchanged, so no callsite churn — only
  the user-visible string moved.
- **PendingQueue's standalone toolbar removed.** "Play All" moves from
  the screen-level TopAppBar into a trailing chip on the filter row
  inside the Pending tab body, so the parent tab host can render a
  single clean header.

## Fixed

- **Portrait lock** (issue #64). The app rendered broken in landscape;
  now it stays vertical on all 10 activities (`MainActivity`,
  `SettingsActivity`, `HistoryActivity`, etc.) regardless of how the
  user holds the device. `android:screenOrientation="portrait"` is set
  per-activity in the manifest — `<application>`-level lock isn't
  honored by Android, so each entry gets the attribute explicitly.

## Removed

- **`PendingQueueActivity`** — its only entry point was the home
  banner, which created the dead-end UX bug above. The Composable +
  ViewModel were preserved verbatim and re-hosted inside
  `HistoryActivity`. The `<activity>` manifest entry is gone.

## Internal

- **`HistoryWithPendingTabsScreen`** in `ui/phone/HistoryScreen.kt` —
  parent screen owning the back arrow + tab row. Reads `initialTab`
  from `HistoryActivity.EXTRA_INITIAL_TAB` (`pending` / `history`,
  default history). Tab selection is wrapped in `rememberSaveable` so
  it survives recomposition.
- **`PendingQueueScreen.kt`** (new file) — `PendingQueueViewModel` +
  `PendingQueueTabContent` extracted out of the deleted
  `PendingQueueActivity.kt`. The Composable is `internal` so
  `HistoryWithPendingTabsScreen` can embed it; helpers stay private.
- **`HistoryTabContent`** — the existing History list body, now
  Scaffold-less. The conversation chooser dropdown and the Clear
  button moved from the deleted TopAppBar into an inline header row
  at the top of the tab body, since the parent tab host now owns the
  TopAppBar.
- **Note on play/stop button consistency.** The plan considered
  extracting a shared `PlayPauseToggle` Composable across
  Home / Pending / History, but on inspection the three call sites use
  intentionally different visual treatments (transport circle in Now
  Playing, chip in History bubbles, Headphones/Stop on Home's "play
  last original" toggle). Forcing them through one shared Composable
  would have meant either a parameter-heavy leaky abstraction or
  losing the visual distinctions. The behavioral consistency the
  issue asks for is already enforced by the singleton
  `PlayReplyUseCase.playbackStatus` — all three screens observe the
  same StateFlow, so playback events propagate everywhere
  automatically.
