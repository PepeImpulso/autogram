# v1.23.0-rc.2 — Phase 5 starter: pick which contact the assistant talks to

Pre-release supersedes rc.1. Phase 1 (manifest registration) is now
verified on the Samsung Galaxy. Phase 2 (voice loop, ships in rc.1)
is unchanged in this build. **New in rc.2: a contact picker at the top
of `AssistantActivity` so the assistant can route the voice note to
any pinned contact, not only the configured primary target.**

## Added

- **Contact picker chip row in the assistant.** When the user invokes
  the assistant gesture and has more than one pinned conversation,
  a horizontal chip strip appears above the mic button. The default
  selection is the configured primary target (Merlín), so the most
  common path is unchanged: gesture → mic → speak → send. Tap a
  different chip to send to that contact instead. The Idle screen
  title updates dynamically — "Talk to Merlín" / "Talk to Ana" / etc.
- **`AssistantViewModel.availableContacts` + `selectedTargetId` +
  `setTargetContact()`** drive the picker. `selectedTargetId` is
  pre-resolved to `ConversationRepository.getActive()?.id` on init,
  so behavior with `setTargetContact` never called is identical to
  rc.1.

## Changed

- **`ContactFilterRow` (shared composable from v1.22.0) gains an
  `includeAllChip: Boolean = true` parameter.** History/Pending pass
  the default (`true`) and keep their leading "All" chip; the
  assistant passes `false` because every assistant turn must resolve
  to a specific contact.
- **`AssistantActivity` layout** — picker chip row at the top
  (visible only in Idle state, with mic permission, and when more
  than one pinned contact exists), then the existing centered Idle/
  Listening/Sending/Waiting content below.
- **`assistant_idle_title_for` string** added to all 6 UI locales —
  the parameterised "Talk to <name>" variant. The original
  `assistant_idle_title` ("Talk to Merlín") is kept as the fallback
  when no contact is selected (e.g. the resolution flow hasn't run
  yet).

## Out of scope (still deferred)

- Phase 4 (screen context capture) — privacy-sensitive, deferred.
- Phase 5 voice-command parsing ("send 'driving' to Ana") — bigger
  scope, future RC.
- Phase 5 read-notifications / calendar / Odoo via OpenClaw —
  Phase 3 is N/A (Telegram MTProto reuse).
- Settings entry for the assistant (toggle, separate target, timeout
  config) — useful but not blocking.
- VAD / auto-stop on silence — user picked tap-to-stop earlier.

## Verification on the Galaxy

1. Pull rc.2 via in-app updater.
2. Trigger assistant gesture → AssistantActivity opens with the chip
   row at top + Merlín-default highlighted + "Talk to Merlín" title.
3. Tap a different chip (e.g. Ana) — title updates to "Talk to Ana".
4. Tap mic, speak, tap stop — verify the voice note lands in Ana's
   chat, not Merlín's.
5. If Ana replies within 60 s, AssistantActivity closes and autoplay
   reads the reply through the existing pipeline.
6. Phase 1 still works (Autogram still in the Default digital
   assistant app picker).
