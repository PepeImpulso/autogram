# v1.17.1 — User-reported fixes: AA visibility, voice shortcut preview, queue state 🚗🔧

Patch release addressing four issues the user hit while dogfooding
v1.17.0 in the car.

## 🐛 Fixed

### Android Auto (priority)

The app icon still wasn't appearing on the car head unit after
connecting the phone. The `CarAppService` had the right intent
filters + `minCarApiLevel`, but was missing two things AA's
launcher checks before rendering a tile:

- **`android:icon` and `android:label` on the `<service>` tag.**
  Without them AA silently hides the app from the launcher grid —
  the intent filter alone isn't enough.
- **`<uses name="notification"/>` in `automotive_app_desc.xml`**,
  so AA recognises the app as a messaging notification receiver
  (needed because we post MessagingStyle + CarAppExtender
  notifications from `IncomingMessageNotifier`).

Also added logcat breadcrumbs to `AutogramCarAppService.onCreate`
and `onCreateSession`, so next time we can tell from logs whether
AA is instantiating the service at all — critical for diagnosing
cases where the "Unknown sources" toggle in Android Auto →
Developer Settings got flipped off by a host update.

### Voice shortcut preview didn't play

The in-editor **Preview** button flipped state to "Playing..." but
no audio came out. Root cause: the preview was going through
`AudioPlayer`, which is tuned for **car playback** — it prefers
Bluetooth routing and requests transient audio focus. If the phone
was connected to a BT headset / car, the preview played there
(far from the user), and when focus was denied outright the
playback was silent.

Replaced the preview path with a standalone `MediaPlayer` on the
phone's default media output. No focus requests, no BT routing —
just plays through the speaker the user is staring at.

### Voice shortcut editor forgot the existing recording

Re-entering the editor on a previously-saved voice shortcut
showed the **Record** button again instead of Preview / Redo,
which implied the saved audio was gone. It wasn't — the editor
just wasn't pre-loading it.

Two fixes stacked:

- Added a `loadExisting(audioPath, duration)` call fired from a
  `LaunchedEffect(initial.id)` when opening the voice editor
  with an existing shortcut. State now starts at `Recorded` so
  Preview and Redo controls render immediately.
- Split `VoiceRecordState` into ephemeral (temp take in cacheDir)
  and persistent (existing shortcut at
  `filesDir/voice_shortcuts/$id.ogg`) variants. `resetVoiceState`
  only deletes ephemeral files — **this avoided a data-loss bug
  where dismissing the editor would have wiped the saved
  shortcut file while editing.**

### Queued-offline banner never cleared

Sending while offline set `sendStatus = QueuedOffline` and
showed "Queued offline" in the status pill. `RetryWorker` later
drained the outbox successfully but the banner stayed — the
worker has no channel to reset `sendStatus`.

The banner now observes `outboxCount` + network state instead
of trusting `SendStatus` alone:

- `outbox == 0` → fall through to Idle / Ready.
- `outbox > 0 && !online` → "Queued offline · N".
- `outbox > 0 && online` → "Sending queued · N" (primary
  container tint so you can see the worker is flushing).

## ✨ Added

- **Description block on the Choose-chat picker.** A short
  orientation card (surface-variant tonal, info icon, one
  sentence) at the top of the picker explaining that the chat
  you pick becomes the active send target. The topic step
  gets its own one-liner too. Localized to all 6 languages.

## Install

Update from 1.17.x. No schema changes. After installing, force-
stop Android Auto on the phone once so it re-scans the app
manifest — otherwise the old service metadata can be cached and
the icon still won't appear.
