# v1.18.0 — AA home rendered on a raw Canvas (Waze-style) 🎨🚗

Every release from v1.17.1 through v1.17.8 fought with AA's
`GridTemplate`: uniform tile sizes, uniform tile layouts, and a
tile budget that forced trade-offs between primary, shortcuts
and secondaries. Making Merlin span "4 tiles worth of space"
next to stacked chips and a small secondaries row isn't
achievable inside `GridTemplate` at all — that template gives
you a supermarket shelf, same size for every item.

v1.18.0 switches the AA home to the **same technique Waze and
Google Maps use**: declare the `androidx.car.app.category.NAVIGATION`
category, return a `NavigationTemplate`, and register as a
`SurfaceCallback` via `AppManager`. AA hands us a raw
`android.view.Surface` and we draw the whole UI ourselves.

## ✨ Changed — AA home

- **Full custom canvas rendering** via a new
  `AutogramSurfaceRenderer` (implements `SurfaceCallback`).
  Layout mirrors the phone home in landscape:
  - **Big Merlin circle** top-left, ~30% width × full content
    height, with the same gold ring + peach mic badge we render
    on the phone's `RecordCircle`.
  - **Shortcut chips** stacked vertically to the right of
    Merlin, rendered as rounded brown pills with a leading
    gold Bolt (text) or peach Mic (voice) icon + the shortcut
    label. Up to three chips visible at once.
  - **Secondary circles** distributed across the bottom row,
    each ~52% the diameter of Merlin. Names below each circle
    in a smaller weight so the hierarchy reads at a glance.
- **Pixel-level click dispatch.** `SurfaceCallback.onClick(x, y)`
  hit-tests the click point against a per-frame region list
  (primary circle, each chip, each secondary) and dispatches
  to the corresponding action on `MainViewModel`'s existing
  use cases — no behaviour regression, just a new renderer in
  front of the same engine.

## 🏗 Architecture notes

- Added `<category>androidx.car.app.category.NAVIGATION</category>`
  to the `CarAppService` intent-filter (alongside MESSAGING +
  IOT). This unlocks `NavigationTemplate` and the
  `AppManager.setSurfaceCallback` API that gates the raw
  surface handoff.
- `AutogramSurfaceRenderer` owns a photo-bitmap cache keyed on
  `(path + file.lastModified)` so the same 7-10 avatars aren't
  re-decoded from disk on every state-change redraw. Drawing
  runs on `Dispatchers.Default`; the Surface lock is short and
  throws are caught.
- `MainScreen`:
  - On `onStart`, registers the surface renderer via
    `AppManager.setSurfaceCallback(this)`.
  - On `onStop`, unregisters (so other screens like the
    recording `MessageTemplate` don't draw over the canvas).
  - Pushes pinned + quick-replies state snapshots to the
    renderer whenever the underlying flows emit, and calls
    `invalidate()` so the template is re-rendered.
- `Screen.onGetTemplate()` now returns
  `NavigationTemplate.Builder().setActionStrip(…).build()` on
  the home path. The action strip (silent toggle + voice-
  command CTA) is rendered by AA over the surface, matching
  Waze's affordance placement.

## Install

Update from 1.17.8. Open Autogram in AA — the home screen
should now look like the phone's home, not like a tile grid.
Merlin occupies the visual left-half of the available space
with the chip shortcuts stacked to the right, and secondary
circles line up across the bottom.

If the surface stays blank or flickers, that means AA denied
the surface request (usually because the user hasn't re-
enabled "Unknown sources" inside Android Auto → Developer
Settings after the app's category list changed). Toggle it
off + on and reconnect.
