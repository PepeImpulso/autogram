# v1.20.18 — Auto-play queue-drain fix + stale Stop icon

Two follow-up bug fixes from testing v1.20.17.

## Fixed

- **Auto-play replies stalled after the first message played.** The
  queue-drain path (`PlayReplyUseCase.playNext` → `playQueued` →
  `playSummaryOrTranscription`) re-checked `ttsPlayer.isSpeaking()`
  inside the lock right after the previous utterance's `onDone`
  fired. Android's `TextToSpeech.isSpeaking()` is an IPC call and has
  a tiny window where it still returns `true` between `onDone` firing
  and the engine's internal idle flag flipping. When the check landed
  in that window, the queued message was re-added to the in-memory
  queue — but its persistent `pending_playbacks` row had already been
  deleted by `playNext`, so nothing else would ever fire. The queue
  stalled and the user had to tap "▶ N pending" manually for every
  reply after the first. This matched the user-reported "auto-play is
  on but messages still queue" symptom exactly. The busy check is now
  gated on `respectUserGates`: user-initiated arrivals still queue
  when something is actively playing, but the internal queue-drain
  call trusts that we just finished the previous utterance and starts
  the next one. `TtsPlayer.speak` already does `QUEUE_FLUSH` so the
  call is safe even if the engine is genuinely lingering.
- **Stale Stop icon on the home-screen headphones toggle after pausing
  in History.** Pause from a History bubble set `playbackStatus` to
  `Paused(messageId)`. The home header treated `Paused` the same as
  `Playing` and lit the Stop icon, even though no audio was actually
  coming out — looked like something was playing when nothing was.
  The header now reflects only `Playing`. Pause/resume controls
  inside the History bubble keep working for users who want them; the
  home-screen Stop affordance only appears when sound is actually
  playing. Tapping the headphones from this state plays the latest
  incoming voice from scratch (the paused MediaPlayer is released by
  `playManually`'s defensive stop along the way).
