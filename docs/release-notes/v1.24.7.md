# v1.24.7 — Android Auto voice routing hardening 🔊🚗

This release removes the last manual guesswork from the "text plays in
the car, voice does not" failure path by treating an active Android Auto
connection as authoritative even when Android's output-device list does
not expose a BUS/USB car sink.

## 🐛 Fixed

- **Voice replies could still route into a muted Bluetooth path while
  Android Auto was active.** `AudioPlayer` previously inferred "AA is
  connected" only from output device types like BUS / USB / HDMI. Some
  projected AA sessions only expose Bluetooth A2DP + phone speaker to the
  app, so Autogram forced `setPreferredDevice(BLUETOOTH_A2DP)`. In many
  cars that A2DP source is muted while Android Auto owns the head unit,
  which made real voice notes silent even though text/TTS still worked.
  A new `CarConnectionMonitor` now reads AndroidX CarConnection state and
  makes `AudioPlayer` leave routing to the OS whenever AA projection is
  active.
- **Voice playback now uses the AA-safe navigation audio path
  automatically in the car.** The previous navigation-prompt switch still
  works, but projected Android Auto sessions now opt voice-file playback
  into `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE` even if the switch is off.
  That mirrors the path that already made text/TTS replies audible on the
  same car setup.

## 🔍 Changed

- **AA playback diagnostics now log the car connection state.** The
  `AudioPlayer.play()` entry log includes requested/effective navigation
  usage plus `carConnection=projection/native/not_connected`, so future
  in-car logs show whether routing was based on Android Auto state or
  device-type inference.
- **Settings test playback is closer to production voice playback.** The
  test tone now uses the configured playback speed and navigation-path
  toggle instead of always playing a WAV at 1x with media usage.

## 🧪 Tests

- Added JVM coverage for Android Auto connection based route selection and
  automatic navigation-usage promotion.

## Install

Use the in-app updater after the GitHub release is published; no setting
change or migration is required.
