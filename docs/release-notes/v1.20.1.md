# v1.20.1 — Twelfth audit: PII scrub now covers exceptions + breadcrumbs 🔒

Twelfth deep audit pass. One real finding related to user privacy:
Sentry's PII scrub was only sanitising the top-level event
message, letting phone numbers and Telegram chat IDs escape to
Sentry via exception `value` fields and breadcrumb `data` maps.
Tightened.

## 🐛 Fixed

### Sentry PII scrub was incomplete

`AutogramApplication.scrubSentryEvent` ran the `LONG_ID_RE` /
`PHONE_RE` replacers against `event.message` and
`beforeBreadcrumb` ran it against `crumb.message`. That's useful
for our own `Timber.e(...)` logs with explicit format strings,
but it misses the two places where TDLib error text actually
tends to leak:

- **Exception values** — e.g. a `TdApi.Error` surfaced as
  `Exception("Telegram 400: CHAT_NOT_FOUND 1234567890")`. The
  numeric chat id would ride along inside `event.exceptions[i].value`
  unscrubbed, and Sentry indexes exception messages by default.
- **Breadcrumb data maps** — our auto-logged HTTP and coroutine
  breadcrumbs sometimes carry string values with phone-like
  shapes through the `data` map.

Both now run through `scrubPii`, so:

- Every attached exception's `value` is redacted.
- Every breadcrumb's `message` plus its `data` map entries (for
  String values) are redacted.

Phone numbers (regexes anchored on `+` or multi-group separators)
and long numeric ids (9+ consecutive digits) get replaced with
`[phone]` / `[id]` before the event is shipped. `event.user` and
`event.request` are still nulled out entirely.

## 🧹 Twelfth pass — what else was audited

- **CarAppExtender notification path post-v1.20.0** — confirmed
  that removing the MESSAGING category from the CarAppService
  does NOT break `Listen` / `Reply` actions on incoming voice
  notifications. Those flow through `NotificationCompat.MessagingStyle`
  + `CarAppExtender`, which Gearhead evaluates per-notification.
- **Hilt modules** (`AppModule`, `GitHubModule`) — clean bindings,
  `OkHttpClient` singleton with redacted-bot-token interceptor.
- **`BaseLocaleActivity`** — minimal, correctly applies
  `LocaleHelper.wrap` in `attachBaseContext`.
- **WorkManager** (`RetryWorker`, `RetentionCleanupWorker`) —
  enqueue policy is `APPEND_OR_REPLACE` with a documented
  rationale; retention schedule is `KEEP` so reschedules are
  idempotent.
- **`AutogramCarAppService.onCreate` FGS bootstrap** — already
  `runCatching`-wrapped against `ForegroundServiceStartNotAllowed`
  on API 31+, so a restricted-start scenario logs a warning
  rather than crashing the car session.
- **`Models.kt` + domain enums** — consistent, no ghost states.
- **`VoiceCommand` regex mapper** — clean, order-insensitive.

## Install

Update from 1.20.0. No migration, no permission changes. The
scrub change only affects what makes it into Sentry crash reports;
nothing in your app's behaviour shifts.
