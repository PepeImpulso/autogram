# v1.8.1 — Security + concurrency audit 🔒

Auditoría de seguridad y concurrencia del código acumulado
M1-M6. 10 defectos reales arreglados — 3 críticos, 5 altos, 2
medios.

## 🐛 Fixed (critical)

- **Backup PBKDF2 iteraciones 100k → 600k**. 100 000 era el
  recomendado en 2020; NIST SP 800-132 en 2024 pide ≥ 600 000 para
  SHA-256. Nuevo magic `AUGBKP02` identifica ficheros v2 (600k);
  los backups escritos por 1.7.x (`AUGBKP01`, 100k) **siguen
  importándose** para no perder datos. Nuevos exports siempre v2.
- **Password en memoria**: la String del Compose state + la
  CharArray del CharArray transfer pueden lingerear hasta GC. Clear
  explícito en dismiss + unmount + zeroización del CharArray tras
  `deriveKey`. Key material del `SecretKeySpec` también zeroizado
  via reflection.
- **`ParcelFileDescriptor` leak** en `AndroidOnDeviceTranscriptionEngine`:
  la cancelación podía carrear con `settle()` y dejar el fd
  abierto. Ahora guardado con `AtomicBoolean` + CAS — cleanup
  corre exactamente una vez sea quien sea el que gane la carrera.
- **Decoder MediaCodec leak** si la decodificación OGG tira a mitad.
  try/finally limpia codec + extractor + temp file.

## 🐛 Fixed (high)

- **Race en `PlayReplyUseCase`** entre dos `playVoiceMessage`
  concurrentes. `kotlinx.coroutines.sync.Mutex` serializa el
  critical section del "start playing".
- **`TtsPlayer.shutdown()`** nunca se llamaba. Ahora engancha
  `Application.onTrimMemory` — cuando la UI queda oculta, liberamos
  el engine TTS. El siguiente `speak` recrea perezoso.
- **`MtprotoReceiverService`** onDestroy re-entrante podía cancelar
  un scope recién creado. Flag `destroyed` guarda.
- **`ConnectivityObserver`** registraba callback DESPUÉS del
  primer `trySend(currentSnapshot())`; cambios entre ambas
  llamadas se perdían. Orden invertido.

## 🐛 Fixed (medium)

- **Sentry PII scrubber**: `beforeSend` + `beforeBreadcrumb` strip
  números de teléfono y IDs largos (chat/message IDs). Además se
  desactiva `isSendDefaultPii` y se null-ean `event.user` y
  `event.request`.
- **`ExportImportUseCase.import`** valida `schemaVersion` del JSON
  — backups de futuras versiones con campos que no sabemos manejar
  surfacean como `UnsupportedVersion` en vez de `Corrupt`.

## Install

Actualización desde 1.8.0. Los backups que hayas hecho antes
(`AUGBKP01`) se pueden importar igual; a partir de ahora los
nuevos son `AUGBKP02` con 6x el coste de cracking bruto-force.
