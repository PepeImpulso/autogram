# v1.23.8 — Security follow-up: media browser, LLM key, updater 🛡️🔐

Defensive sweep over issue [#70](https://github.com/PepeImpulso/autogram/issues/70).
Issue #69 hardening verified to still hold; this release closes the
remaining actionable items from the follow-up audit.

## 🛡️ Security (issue #70)

- **[HIGH] MediaBrowserService now rejects untrusted callers.**
  `AutogramMediaBrowserService.onGetRoot()` previously returned a
  non-null root for any package, letting an arbitrary installed app
  enumerate the pending / history catalog (conversation titles, voice
  timing) and trigger playback by guessing a `mediaId`. Added
  `MediaBrowserCallerValidator`, a small dedicated trust gate that
  allows our own UID, the system UID (1000), and a hardcoded allowlist
  of media-host packages whose signing certificate matches a known
  SHA-256 fingerprint:
  - Android Auto / Gearhead (`com.google.android.projection.gearhead`)
  - Android Automotive templates host (`com.google.android.apps.automotive.templates.host`)
  - Google Assistant (`com.google.android.googlequicksearchbox`)

  Untrusted callers receive `null` from `onGetRoot`, which AndroidX
  translates to "this client cannot browse" — `onLoadChildren` is never
  reached and an untrusted controller cannot acquire the session token
  to call `onPlayFromMediaId`. Debug builds keep a permissive fallback
  so DHU and local test apps still work without importing every test
  signature.

- **[MEDIUM] LLM summarisation API key moved to encrypted storage.**
  `summaryLlmApiKey` was a plaintext column in `settings`, exposing it
  to forensic extraction, root-level extraction and adb backups. New
  `LlmApiKeyStore` wraps `EncryptedSharedPreferences` with the same
  Android Keystore-backed master key TDLib already uses. On first read
  after upgrade, `SettingsRepositoryImpl` copies any existing plaintext
  key into the encrypted store and blanks the Room column; subsequent
  writes never round-trip through Room. Fresh installs never persist a
  plaintext value at all. The Room column stays as a v0-shaped
  breadcrumb — to be dropped in a future schema migration.

- **[MEDIUM] DownloadManager receiver registered as
  `RECEIVER_NOT_EXPORTED`.** `UpdateInstaller` had to use
  `RECEIVER_EXPORTED` on Android 13+ when the flag became mandatory;
  swap to `RECEIVER_NOT_EXPORTED` is fine because
  `ACTION_DOWNLOAD_COMPLETE` is a protected system broadcast and the
  platform still delivers it. A third-party app can no longer spoof
  `ACTION_DOWNLOAD_COMPLETE` to confuse the in-app updater.

- **[LOW] Sentry Android upgraded `7.20.0 → 8.14.0` (CVE
  GHSA-7cjh-xx4r-qh3f).** No Session Replay configuration was added —
  the advisory's preconditions were never met, but staying on the
  vulnerable line is unnecessary risk. Crash-reporting init path
  unchanged; no API surface used by Autogram broke between 7 and 8.

- **[LOW] Stale security docs refreshed.** `docs/04-data-model.md`,
  `docs/05-risks.md` and `docs/06-development-plan.md` were still
  describing `Conversation.botToken` as a stored field and bot-token
  leakage as the dominant credential risk. Updated to reflect the
  MTProto/TDLib auth model, the per-install Keystore-wrapped TDLib
  database key, the encrypted LLM API key, and the migration that
  removed the legacy plaintext column.

### Out of scope (filed for v1.24+)

- **APK SHA-256 digest verification before install.** Adds defence in
  depth, but Android already enforces signature verification at
  install time (a different signer is rejected by the package
  installer). Needs a CI workflow change to publish `.sha256`
  alongside the APK plus an app-side verifier — keeping it out of this
  hotfix to limit the diff.

after upgrade and the encrypted store takes over from there.
