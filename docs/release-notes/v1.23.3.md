# v1.23.3 — Replay-last covers every circle + AA crash hotfix 🎧🛠️

Two on-device issues Pepe surfaced after testing v1.23.2.

## 🐛 Fixed

- **Receiver · ForegroundServiceStartNotAllowedException no longer
  crashes the app when Android Auto binds in the background.**
  `AutogramCarAppService.onCreate` calls
  `ContextCompat.startForegroundService(MtprotoReceiverService)` so
  TDLib is hot before the user taps Record on the car screen. On
  Android 12+ the system can refuse that FGS start when the host
  app is fully backgrounded (Sentry: ID `9c68b9…`,
  `release=autogram@1.23.0-rc.6+105`, `os=Android 15`). The
  exception fires asynchronously inside `MtprotoReceiverService.onCreate`
  on the binder thread, so the `runCatching` wrapper at the call
  site never sees it — it propagates through
  `ActivityThread.handleCreateService` and takes the process down.
  Fix: wrapped the `startForeground` block in
  `MtprotoReceiverService.onCreate` with a `try { … } catch
  (IllegalStateException)` (the supertype of
  `ForegroundServiceStartNotAllowedException`, also covers OEM forks
  that throw the plain superclass). On denial we log a Timber
  warning and `stopSelf()`; the next foreground entry — MainActivity
  resume or an AA session start — re-creates the service in an
  allowed context, so TDLib still comes up the moment the user
  actually interacts with the app.

- **HeroHeader · "Replay last" now picks up the most recent message
  from any circle, not only voice notes from the primary one.**
  The `LIMIT 1` DAO query feeding the headphones toggle had a
  `WHERE … audioFilePath IS NOT NULL` clause, so text replies were
  invisible to it. With Merlin being the only voice-sending circle,
  Pepe always heard Merlin even when a newer text reply had arrived
  from another circle (e.g. CMO – Marketing). Relaxed the filter to
  match incoming rows where audio OR `textContent` is present —
  symmetric with how `MtprotoReceiverService.handleText` and
  `handleVoiceNote` insert each row, so anything the receiver
  enqueues is also a candidate for the replay button.
  `PlayReplyUseCase.playManually()` already routes audio→audio and
  no-audio→TTS, so text rows get spoken aloud through the same code
  path the live-arrival flow uses.

## 🔧 Internal

- **MessageRepository · `observeLatestIncomingVoice` →
  `observeLatestIncoming`.** Same rename in `MainViewModel`
  (`lastIncomingWithAudio` → `lastIncoming`) and `MainActivity`. The
  field name was misleading after the query relaxation — it now
  matches voice OR text, not voice with audio.
