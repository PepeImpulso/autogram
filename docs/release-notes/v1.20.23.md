# v1.20.23 — Pending Queue screen + History redesign

Two big premium-feel upgrades from the marketing-mockup pass: a
dedicated Pending Queue screen with its own Now Playing transport, and
a redesigned History with proper voice waveforms and distinct
Transcription / AI Summary cards.

## Added

- **Pending Queue screen.** Tapping the "▶ N Pending" button on Home
  no longer drains the queue immediately — it opens a full screen
  showing exactly what's queued, with a per-message avatar, speaker
  name, "Voice message · 0:28" / "Text message" subline, and arrival
  time. Tap a row to start playback from there; tap "Play All" in the
  toolbar to drain in order. A Now Playing panel pinned at the bottom
  shows the active message with a waveform progress bar, time
  markers, and three transport buttons:
    - ⏮ Restart current message from the start
    - ⏯ Pause / Resume
    - ⏭ Skip to the next message in the queue
  Filter pills (All / Voice / Text) at the top let you focus on one
  kind of reply. The queue now works as a proper hold area — you
  decide when to listen, in what order.

## Changed

- **History bubble redesign.** Voice messages in History now render
  with a proper waveform visual (decorative — deterministic per
  message id, so the same message always looks the same) instead of
  the small icon + "Voice note · duration" line. While a message is
  actively playing in History, the waveform paints in tertiary gold;
  otherwise it sits in a muted grey.
- **Transcription / AI Summary cards.** Both inset blocks inside an
  incoming voice bubble now use distinct hues: AI Summary lives in a
  warm brown (`tertiaryContainer`) and Transcription in the neutral
  `surfaceContainerHigh`. Both cards now show the inferred label
  ("AI Summary" / "Transcription") and a right-aligned timestamp,
  matching the marketing mockup's card aesthetic.

## Internal

- **`MessageRepository.observePendingPlaybackQueue()`** — new Flow
  joining `messages` ⨝ `pending_playbacks` so the screen can render
  queue contents in actual drain order rather than just "all rows
  with `state = PENDING_PLAYBACK`".
- **`MessageRepository.observeNowPlaying()`** — Flow of the single
  `state IN ('PLAYING', 'PAUSED')` row for the Now Playing panel.
- **`AudioPlayer.currentPositionMs() / durationMs()`** — pass-through
  to `MediaPlayer` so the Now Playing scrubber can poll position
  every 250 ms while playback is active. Both wrapped in
  `runCatching` to absorb the `IllegalStateException` MediaPlayer
  throws when queried in an Error state.
- **`PlayReplyUseCase.skipNext() / restartCurrent()`** — driven by
  the Now Playing transport. `skipNext` stops current playback and
  pops the next queued message via the existing `playNext()` chain.
  `restartCurrent` re-routes the currently-playing message back
  through `playQueued` after a hard stop.
- **Shared `Waveform` composable** — extracted to
  `ui/phone/Waveform.kt` so both PendingQueueActivity and
  HistoryScreen render the same deterministic-pseudo-amplitude
  visual without duplication.
