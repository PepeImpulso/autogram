# v1.20.15 — Critical fix: per-badge tap was deleting message history

A serious data-loss bug introduced by v1.20.14 went undetected by tests
because no test touched the foreign-key relationship between
`conversations` and `messages`. **Update to v1.20.15 immediately;
v1.20.14 should be considered unsafe.**

## Fixed

- **CRITICAL: Tapping a per-circle pending badge wiped that
  conversation's local message history.** v1.20.14's "acknowledge on
  view" used `conversationRepository.upsert(...)` to bump
  `conversations.lastRepliedAt`. The DAO's upsert is
  `@Insert(onConflict = REPLACE)`, which SQLite implements as
  DELETE-then-INSERT on the conflicting row — and the `messages` table
  has `ForeignKey(onDelete = CASCADE)` referencing `conversations.id`,
  so every message for the tapped conversation got CASCADE-deleted by
  the upsert. Then the empty-History view was correct: the messages
  had just been destroyed. Switched to `setLastRepliedAt` (a plain
  targeted UPDATE) which has no FK side-effects. Audited every other
  `conversationRepository.upsert` call site — the rest pass brand-new
  UUIDs, so no PK conflict, no REPLACE, no CASCADE. They're safe.
- **Note on already-lost data.** Messages destroyed by v1.20.14 are
  gone from local storage. They still exist on Telegram's servers but
  Autogram's TDLib sync only pulls forward from the most-recent local
  message, so they won't auto-restore. If you need an old message
  back, open the chat in any other Telegram client and it'll be there.

## Changed

- **Screenshot button now appears on every screen, not just Home.**
  v1.20.14 put the camera icon in the Home header. v1.20.15 replaces
  it with a global floating action button in the bottom-right corner
  that follows you to History, Settings, Stats, Manage Pinned, etc.
  Same behaviour: tap → capture current screen → save to
  Pictures/Autogram → open the system share sheet. Still off by
  default; controlled by Settings → Diagnostics → Developer mode.
