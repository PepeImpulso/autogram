# v1.22.1 — Audio finally plays through the car speakers

Pepe reported that on his Galaxy connected to the car (USB Android Auto
+ Bluetooth simultaneously), incoming voice messages played in absolute
silence — he had to disconnect the phone to listen. **Fixed.**

## Root cause

`AudioPlayer` already set the right `AudioAttributes` (`USAGE_MEDIA` +
`CONTENT_TYPE_SPEECH`) and requested audio focus correctly. What it
*didn't* have: a registered `MediaSession`. On USB Android Auto the
phone speaker is muted by AA's audio policy, and AA only opens its
media stream for apps with a registered `MediaSession` it can observe
— without one, audio plays into the void.

In short: Autogram was technically a "messaging app" to the OS, not a
"media app". Music apps work in the car because they own a
`MediaSession`; we didn't.

## What changed

### Added

- **`AutogramMediaPlaybackController`** (singleton). Wraps a
  `MediaSessionCompat`. PlayReplyUseCase calls `markPlaying` /
  `markPaused` / `markStopped` as the underlying `AudioPlayer` /
  `TtsPlayer` state changes. Android Auto / Bluetooth car / lock-
  screen media controls observe the same session.
- **`AutogramMediaBrowserService`** — `MediaBrowserServiceCompat`
  registered with the `android.media.browse.MediaBrowserService`
  intent filter. **Autogram now appears in Android Auto's media
  tab** alongside Spotify / Apple Music, with a browseable catalog:
    - **Pending** — current pending playback queue
    - **History** — last 50 incoming voice messages
  Tapping a message in the car routes through the session callback
  to `PlayReplyUseCase.playFromHere`.
- **`<uses name="media" />`** in `automotive_app_desc.xml` —
  declares Autogram as a media-capable Android Auto app (alongside
  the existing `template` for the messaging UI).

### Changed

- **`PlayReplyUseCase`** wires AA / car-stereo / lock-screen
  transport callbacks (Play / Pause / Stop / Skip / PlayFromMediaId)
  back into its existing methods. AA's pause button on the steering
  wheel now actually pauses Autogram's playback.

## Internal

- `androidx.media:media:1.7.0` added — provides
  `MediaBrowserServiceCompat` + `MediaSessionCompat`. Battle-tested
  for Android Auto media-app integration.
- `FOREGROUND_SERVICE_MEDIA_PLAYBACK` permission declared. Not used
  by an active foreground service today, but covers the case if we
  promote `AutogramMediaBrowserService` to foreground later (e.g.
  for resilience against process death during long playback).
- `CarAppService` (templated messaging UI for AA) is unchanged —
  Pepe asked to "decide later" so it stays. The two surfaces
  (messaging template + media browser) coexist; the manifest-merger
  routing rules already account for both.

## Verification on the Galaxy

1. Pull v1.22.1 via in-app updater.
2. Connect phone to car (USB AA + BT).
3. **Driver-seat test:** receive a voice message. Should auto-play
   through the car speakers if you have auto-play on. Compare
   subjectively to Spotify routing.
4. **Pending queue test:** receive 2-3 messages with auto-play off.
   Tap "▶ N pending" on the home screen. Each message should play
   through the car speakers in sequence.
5. **Browse test:** on the car dashboard, open the media tab. Look
   for Autogram. Tap → see "Pending" + "History" folders → tap a
   history message → plays through car speakers.
6. **Transport test:** while Autogram audio is playing, tap pause
   on the steering wheel / car dash → Autogram pauses. Tap play →
   resumes.

If audio still doesn't reach the car, check whether Autogram appears
in the car's media tab. If yes but audio still goes nowhere, that
points to AA's audio policy on this specific car / Gearhead version
— ping back with One UI version + car make/model and we'll dig
further.
