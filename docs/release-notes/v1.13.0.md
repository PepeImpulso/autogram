# v1.13.0 — Shortcut folders 📁

**Closes out the 16-item roadmap.** When you accumulate many
pinned circles, folders group them into tabs on the main
screen so the grid stays scannable.

## 🗄 Schema

- New `circle_folders(id, name, color, sortOrder)` table.
- `ConversationEntity.folderId: String?` — nullable reference
  (no FK) (null = "no folder", shows up under "All" but never
  gets filtered into a specific tab).
- Migration **v12→v13** creates the table and adds the column
  non-destructively, so existing users find their circles
  exactly where they were.

## 🧩 Domain / repo

- `CircleFolder` data class + `CircleFolderRepository` bound via
  Hilt.
- `ConversationRepository.setFolder(id, folderId)` + DAO query.
- **Folder deletion** sets `conversations.folderId = NULL`
  first — atomic, members survive and fall back to "All".

## ✨ ManagePinned UI

- New "Folders" card above the list with a horizontal chip
  row: one chip per folder + a "New folder" outlined one at
  the end. Tap → `AlertDialog` with `OutlinedTextField` for
  the name. Long-press on an existing chip → confirmation
  dialog that spells out the non-destructive behavior in the
  copy.
- Each circle's overflow menu gains a folder sub-section:
  radio-style entries for "No folder" + each configured
  folder, with the current one marked with a `primary` star.

## ✨ MainActivity

- **`FolderTabRow`** above the primary circle, visible only if
  there's at least one folder created. `LazyRow` of
  `FilterChip`s, the first item is always "All"
  (`selectedFolderId = null`). The primary circle stays
  visible across all tabs; only secondaries are filtered.
- `MainViewModel` exposes `folders` + `selectedFolderId` as
  StateFlows, so the selected tab survives round-trips through
  the bottom nav.

## Install

Update from 1.12.x. Strings localized into the 6 languages.
Users without folders don't see the new UI — it only appears
when the first one is created.
