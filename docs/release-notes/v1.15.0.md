# v1.15.0 — Chips contextuales con LLM configurado 💬🤖

El sugeridor de chips por reglas regex (v1.9.0) era determinista pero
limitado a los patrones que hardcodeamos. v1.15.0 **superpone el
endpoint OpenAI-compatible que el usuario ya configuró**: cuando
`summaryEngine == LLM_ENDPOINT`, un mensaje entrante dispara también
una llamada LLM pidiendo 2-3 respuestas cortas adaptadas al contenido
real. Si el LLM está off, lento o devuelve basura, caemos al baseline
de regex — los chips siguen apareciendo para los patrones que
conocemos.

## 🏗 Architecture

- **`LlmQuickReplySuggester`** en `infrastructure/suggestion/`.
  Reutiliza el mismo endpoint / API key / modelo que lee el motor
  de resumen — **un knob de config, dos features**. System prompt
  pide un JSON array estricto de strings (max 5 palabras cada uno,
  en el idioma del mensaje) + parser tolerante que strippea fences
  ` ```json ` y preámbulos estilo chat antes de `JSON.parse`, para
  que un modelo que ocasionalmente añade "Here are..." siga
  funcionando.
- **`SuggestQuickReplyUseCase.suggestFor`** ahora es `suspend`.
  Llama al LLM con timeout hard de 3.5s (más y abandonamos); en
  éxito el LLM gana; en empty/timeout/exception cae silenciosamente
  al matcher de regex existente. `matchRegexRules(...)` pública
  se mantiene para callers que quieran solo regex (e.g. futuro
  toggle de debug).
- `MainViewModel.init` ya colectaba sugerencias dentro de
  `viewModelScope.launch`, así que la firma suspend entra limpia —
  el único cambio visible es un delay de 0.5-3s antes de que
  aparezcan los chips LLM, aceptable porque reemplazan el resultado
  regex.

## 🧪 Tests

- Tests MockK del use case: rama LLM-success-wins, fallback
  LLM-empty, fallback LLM-throw, dedup case-insensitive del output
  LLM. Los 9 tests de reglas regex originales ahora mockean el LLM
  a `emptyList()`, así siguen ejercitando el path fallback.
- Nuevo `LlmQuickReplySuggesterTest` con 9 tests del parser JSON:
  array limpio, fence ` ```json `, fence ` ``` ` pelado, extracción
  de preámbulo, cap de límite, drop de items blancos, input vacío,
  input no-JSON, brackets malformados.
- `testImplementation("org.json:json:20240303")` añadido para que
  los tests unitarios tengan parser JSON real en vez del stub de
  Android. **43 tests, 0 fallos.**

## Install

Actualización desde 1.14.x. Sin cambios de esquema. Si ya tenías el
endpoint LLM configurado para resumen, los chips contextuales
empezarán a usarlo automáticamente. Si no, siguen las reglas regex
sin cambios.
