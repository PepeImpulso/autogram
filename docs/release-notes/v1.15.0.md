# v1.15.0 — Contextual chips with configured LLM 💬🤖

The regex-rule chip suggester (v1.9.0) was deterministic but
limited to the patterns we hardcoded. v1.15.0 **layers in the
OpenAI-compatible endpoint the user already configured**: when
`summaryEngine == LLM_ENDPOINT`, an incoming message also fires
an LLM call asking for 2-3 short replies tailored to the real
content. If the LLM is off, slow or returns garbage, we fall
back to the regex baseline — chips still appear for the
patterns we know.

## 🏗 Architecture

- **`LlmQuickReplySuggester`** in
  `infrastructure/suggestion/`. Reuses the same endpoint / API
  key / model the summary engine reads — **one config knob, two
  features**. System prompt asks for a strict JSON array of
  strings (max 5 words each, in the message's language) +
  tolerant parser that strips ` ```json ` fences and chat-style
  preambles before `JSON.parse`, so a model that occasionally
  adds "Here are..." keeps working.
- **`SuggestQuickReplyUseCase.suggestFor`** is now `suspend`.
  It calls the LLM with a hard 3.5s timeout (beyond that we
  give up); on success the LLM wins; on empty/timeout/exception
  it silently falls back to the existing regex matcher. Public
  `matchRegexRules(...)` stays for callers that want regex only
  (e.g. a future debug toggle).
- `MainViewModel.init` was already collecting suggestions
  inside `viewModelScope.launch`, so the suspend signature
  slots in cleanly — the only visible change is a 0.5-3s delay
  before the LLM chips appear, acceptable because they replace
  the regex result.

## 🧪 Tests

- MockK tests for the use case: LLM-success-wins branch,
  LLM-empty fallback, LLM-throw fallback, case-insensitive
  dedup of the LLM output. The 9 original regex-rule tests now
  mock the LLM to `emptyList()`, so they keep exercising the
  fallback path.
- New `LlmQuickReplySuggesterTest` with 9 JSON-parser tests:
  clean array, ` ```json ` fence, bare ` ``` ` fence, preamble
  extraction, limit cap, blank-item drop, empty input,
  non-JSON input, malformed brackets.
- `testImplementation("org.json:json:20240303")` added so unit
  tests have a real JSON parser instead of Android's stub.
  **43 tests, 0 failures.**

## Install

Update from 1.14.x. No schema changes. If you had the LLM
endpoint configured for summary, contextual chips will start
using it automatically. If not, regex rules keep running
unchanged.
