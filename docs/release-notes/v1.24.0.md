# v1.24.0 — AA audio routing fix + UI revamp 🔊🚗

Targets two driving-blocker issues at once: voice + TTS playback now
actually reaches the car speakers on Android Auto, and the AA car-screen
is no longer a single conversation list — it's a four-tab home with
shortcuts, pending queue, and in-car settings.

## 🔧 Fixed

- **AA · Voice/TTS playback didn't reach the car speakers.**
  `MtprotoReceiverService` ran as a `dataSync|specialUse` foreground
  service. On Android 14+ the background-audio policy can silently
  suppress media playback triggered from a foreground service that
  doesn't declare `mediaPlayback` — even with a valid MediaSession
  active, even with USAGE_MEDIA + CONTENT_TYPE_SPEECH attributes set.
  Promoted the service type to `dataSync|specialUse|mediaPlayback` and
  passed `FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK` in the
  `startForeground` call so the system now treats Autogram's playback as
  legitimate. The `FOREGROUND_SERVICE_MEDIA_PLAYBACK` permission was
  already declared in the manifest — it just wasn't being exercised.

## ✨ Added

- **AA · Four-tab home (TabTemplate).** The Android Auto home screen is
  now a `TabTemplate` instead of a single `ListTemplate`:
  - **Inbox** — the messaging list with inline reply + per-row Record
    (unchanged from v1.23.x).
  - **Shortcuts** — tap-to-send grid of enabled quick replies. Each
    tile sends through `SendVoiceMtprotoUseCase.sendQuickReply` and
    respects per-shortcut contact pinning.
  - **Pending** — messages waiting to play, with a "Mark all as
    listened" action. Tapping a row plays from that point.
  - **Settings** — driver-safe `PaneTemplate` with cycle buttons for
    auto-play, playback speed (0.75–2.0×), audio focus mode, and
    "TTS as nav prompt" toggle. No sliders / dropdowns in the car (AA
    distraction rules) — every row tap cycles to the next preset.

- **Phone Settings · AA audio routing section.** New card under
  Playback that exposes three controls plus a "Test playback in car"
  button:
  - **Audio focus mode** — three-way picker (`TRANSIENT_MAY_DUCK` /
    `TRANSIENT_EXCLUSIVE` / `GAIN`). The default is unchanged; switch
    to a stricter mode if the AA host is muting the soft request.
  - **Speak text as navigation prompt** — toggles TTS audio attributes
    from `USAGE_MEDIA` to `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE` (the
    same path Google Maps directions use). Routes over music on most
    cars; off by default.
  - **Test playback in car** — synthesises a 600 ms tone, plays it
    through the production `AudioPlayer` + audio focus mode, then
    follows with a short TTS sample. Park, tap, listen — switch mode
    if you didn't hear it through the speakers.

- **Phone Settings · "Last playback route" diagnostic.** Shows the
  `AudioDeviceInfo.TYPE_*` of wherever the MediaPlayer was routed last
  ("Bluetooth A2DP", "Bus (Android Auto media stream)", "Phone
  speaker (audio did NOT reach the car)", …). Lets you confirm in the
  car whether playback went where you expected without checking logs.

## 🔍 Changed

- **AA Media tab — Pending folder removed.** The Media tab used to
  expose `Pending` + `History`. The new CarAppService Pending tab is
  now canonical; keeping a duplicate in the Media tab confused users
  who tapped into a browse-only surface with no reply path. Media tab
  still shows `History` for listen-back. The legacy folder ID returns
  an empty list so cached browsers don't error.

## 🛠️ Internal

- **Room migration v19 → v20.** Two new `settings` columns:
  `audioFocusMode TEXT NOT NULL DEFAULT 'TRANSIENT_MAY_DUCK'` +
  `ttsAsNavigationPrompt INTEGER NOT NULL DEFAULT 0`. ALTER TABLE; no
  recreate-dance needed.
- **`AudioPlayer` is now `@Singleton`** so the `lastRoutedDeviceType`
  StateFlow has a stable subscriber surface for the Settings
  diagnostics card.
- **`AudioPlayer.play()` signature gained `focusMode: AudioFocusMode`
  parameter** (defaults preserve v1.23.x behaviour). Call sites in
  `PlayReplyUseCase` now pass `settings.audioFocusMode`.
- **`SettingsViewModel` injects `AudioPlayer` + `TtsPlayer`** for the
  Test Playback button.

### Deferred to a follow-up

- **Reply custom action on the now-playing card.** Would let the user
  tap a "Reply" button next to play/pause and send a default quick
  reply to the currently-playing message's conversation. Requires
  cross-use-case wiring (PlayReplyUseCase needs `SendVoiceMtprotoUseCase`
  to invoke the send path). Tracked for v1.24.1.
- **Per-conversation detail Screen.** Inbox tab's `ConversationItem`
  rows already support inline reply + Record, which covers the core
  flow; a separate `PaneTemplate` showing the last 3 messages with
  bulk-action buttons is a nice-to-have, not a blocker.
