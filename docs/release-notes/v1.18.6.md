# v1.18.6 — Fix double playback (voice + TTS overlap) 🔊🛑

User reported incoming messages played in two voices at once — a
correct Spanish voice and a separate English voice reading Spanish
on top of it. Root-caused to three related issues, fixed here.

## 🐛 Fixed

### Concurrent audio + TTS engines

When Merlin replies with both a voice note **and** a text (common
with AI-assistant bots that send both the recorded audio and a
text summary), `MtprotoReceiverService` fired
`playReplyUseCase.playVoiceMessage()` on the `.ogg` via
`AudioPlayer` **and** `playReplyUseCase.playTextMessage()` via
`TtsPlayer` on the text. They're independent engines, so both
played simultaneously.

- **`playTextMessage` and `playSummaryOrTranscription` now take
  the same `playbackStartLock` that `playVoiceMessage` uses.**
  If audio is already playing (or TTS is already speaking), the
  text message gets enqueued in the pending queue instead of
  speaking over it. `playNext` then picks it up after the
  current playback finishes.

### TTS queue accumulation

`TtsPlayer.speak(text, QUEUE_ADD, …)` caused sequential calls to
stack: the old utterance kept playing while the new one also
started. Switched to **`TextToSpeech.QUEUE_FLUSH`** with an
explicit `tts.stop()` before each `speak()`, so only one
utterance is ever in flight.

### English voice reading Spanish

`playTextMessage` called `ttsPlayer.speak(text)` with no locale
parameter, so TTS fell back to the UI locale. If the user was in
an English-UI context, Spanish replies got read with an English
voice.

- **Content-based locale detection added** via
  `TtsPlayer.detectLocale(text, fallback)` (same function
  `playSummaryOrTranscription` already used). Spanish markers
  (`ñ`, `á`, `é`, `í`, `ó`, `ú`, `¿`, `¡`) or CJK blocks
  override the UI locale so the text is read with its native
  voice.

## 🏗 Implementation

- `PlayReplyUseCase.kt`:
  - `playTextMessage`: wrapped body in `playbackStartLock.withLock`;
    early-out to `pendingQueue` when audio/TTS already active;
    detect locale via `TtsPlayer.detectLocale`.
  - `playSummaryOrTranscription`: same lock + enqueue-if-busy
    pattern (the locale-detect was already present).
- `TtsPlayer.kt`:
  - `speak()`: `tts.stop()` before enqueue + `QUEUE_FLUSH` flag.
  - New `isSpeaking()` helper for the usecase-layer check.

## Install

Update from 1.18.5. Next time Merlin sends a combined voice+text
reply, you should hear the voice note play first and the text
read aloud afterwards (in the correct Spanish voice), instead of
both voices at once.
