# v1.7.1 — Post-release polish + a real incoming-text bug 🔧

1.7.0 revisit after a lot of testing, plus **a real bug**
uncovered in the process: incoming **text** messages from
Telegram were being silently ignored. Only voice was being
processed.

## 🐛 Fixed

- **Incoming text ignored**. `MtprotoReceiverService` only
  handled `MessageVoiceNote`; `MessageText` was dropped with a
  `Timber.d`. Now persisted, notified via the existing notifier
  (with preview truncated to 120 chars) and read via TTS
  respecting the same gates as voice (silent mode, in-call,
  autoPlayReplies). The plumbing already existed since 1.6.0, but
  the handler was missing.
- `PlayReplyUseCase.playNext`: when a queued message is text (no
  `audioFilePath`) it now routes to TTS; before it tried to hand
  it to `MediaPlayer` which failed.

## ✨ Added

- **Minimum 8-character backup password**. A 1-character
  password made the KDF trivial; the UI now rejects it with a
  localized message.
- **Onboarding "press and hold" step**: animated microphone with
  pulse-ring instead of the static icon — the gesture is
  demonstrated visually.
- **Onboarding "pick recipient" step**: auto-advances to the
  next step when the user returns with a chosen target, without
  having to tap "Next".
- **Backup import applies locale automatically**:
  `AppCompatDelegate.setApplicationLocales` + Activity
  `recreate()` — no more having to restart the app to see the
  restored language.

## Install

Update from 1.7.0. If you had text messages waiting in Telegram,
they'll start being processed normally after updating.
