# v1.7.1 — Pulido post-release + bug real en texto entrante 🔧

Repaso de la 1.7.0 después de mucho testing, más **un bug real**
descubierto en el proceso: los mensajes de **texto** entrantes de
Telegram se estaban ignorando silenciosamente. Solo los de voz se
procesaban.

## 🐛 Fixed

- **Texto entrante ignorado**. `MtprotoReceiverService` solo
  manejaba `MessageVoiceNote`; los `MessageText` se descartaban con
  un `Timber.d`. Ahora se persisten, notifican vía el notifier
  existente (con preview truncado a 120 chars) y se leen por TTS
  respetando los mismos gates que la voz (silent mode, in-call,
  autoPlayReplies). El plumbing ya existía desde 1.6.0, pero
  faltaba el handler.
- `PlayReplyUseCase.playNext`: cuando un mensaje en cola es texto
  (no tiene `audioFilePath`) ahora se rutea a TTS; antes intentaba
  pasarlo al `MediaPlayer` que fallaba.

## ✨ Added

- **Contraseña de backup mínimo 8 caracteres**. Un password de 1
  carácter hacía el KDF trivial; ahora la UI lo rechaza con
  mensaje localizado.
- **Onboarding paso "press and hold"**: micrófono animado con
  pulse-ring en lugar del icono estático — el gesto se demuestra
  visualmente.
- **Onboarding paso "elige destinatario"**: auto-avanza al paso
  siguiente cuando el usuario vuelve con un target elegido, sin
  tener que tap "Siguiente".
- **Import de backup aplica locale automáticamente**:
  `AppCompatDelegate.setApplicationLocales` + recreate() de la
  Activity — ya no hay que reiniciar la app para ver el idioma
  restaurado.

## Install

Actualización desde 1.7.0. Si tenías mensajes de texto esperando
en Telegram, tras actualizar empezarán a procesarse normalmente.
