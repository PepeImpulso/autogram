# v1.19.5 — Fix Android Auto blank-screen crash on launch 🚗💥

A single, hard bug: every Android Auto session since v1.19.1 has
crashed on the very first frame with an `IllegalArgumentException`
coming out of the renderer's `init` block. The car displayed
Autogram's name in the launcher and then, once tapped, showed the
stock AA fallback text *"No messages received while driving"* —
because our `Screen` never got to present a template. The host
swallowed the exception, killed the session, and showed its
generic empty state.

## 🐛 Fixed

### `IllegalArgumentException: CONFLATED capacity cannot be used with non-default onBufferOverflow`

Introduced in v1.19.1 when I added the custom-canvas
`AutogramSurfaceRenderer`. The draw pipeline uses a conflated
`Channel<Unit>` so that bursts of render requests (state flow +
shortcuts flow + recording flow + visible-area change all emitting
in quick succession) collapse into a single frame. The
construction was:

```kotlin
Channel<Unit>(
    capacity = Channel.CONFLATED,
    onBufferOverflow = BufferOverflow.DROP_OLDEST
)
```

That combination is rejected by the `Channel(...)` factory at
**construction time** — `CONFLATED` already implies its own
"keep latest, drop older" overflow semantics and is mutually
exclusive with any explicit `onBufferOverflow`. The exception
fires in the renderer's `init`, which runs the first time
`MainScreen` builds a `NavigationTemplate`, which happens the
first time AA calls `onGetTemplate()` — i.e. the first time the
user opens Autogram on the car screen.

Fix is one line:

```kotlin
val drawChannel: Channel<Unit> = Channel(capacity = Channel.CONFLATED)
```

The semantics are identical; the explicit `DROP_OLDEST` was
redundant.

Confirmed against Sentry event `44821d8d` and stack frame
`androidx.car.app.CarAppBinder.lambda$onAppCreate$0`. All AA
surface sessions on v1.19.1 → v1.19.4 crashed here; phone-app
functionality was unaffected because the renderer is only
instantiated inside the CarAppService.

## 🔍 Audit retrospective — why six passes missed this

Every prior audit in the v1.19.x series looked at logic
(race conditions, state machines, retry policies, bounds
checks). None of them would have caught this, because the
misconfiguration compiles and passes lint — it only throws at
runtime, at the moment of `Channel(...)` invocation. The
contract is enforced in `ConflatedBufferedChannel.<init>` via
an `require()` check inside `kotlinx.coroutines`. Static
analysis cannot see it.

Lesson for the pattern: when a factory function's documented
constraints include mutually exclusive parameters, treat that
as a runtime-only invariant and test-construct the object at
startup, or move the construction into a place where the
first exercise is covered by an actual Android-test run.

This is the first real bug found in the AA path beyond the
initial wiring (manifest permissions, category). The renderer
logic itself — drawing, hit-testing, bitmap caches, click
dispatch — remains clean.

## 🧪 Running tally

**36 real bugs fixed across six audit passes** (11 + 6 + 9 + 4

## Install

Update from 1.19.4 and reconnect the phone to the car (or
DHU). The Autogram launcher tile should now open to the full
home screen — big Merlin circle top-left, secondary pinned
circles in the grid, shortcut chips on the right — instead of
the AA empty-state fallback. No migration, no permission
re-grant.
