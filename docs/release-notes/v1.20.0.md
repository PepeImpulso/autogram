# v1.20.0 — Android Auto launcher fix + car-audio routing fix 🚗🔊

Two related bugs that have dogged every release since v1.18.1,
both fixed after a focused deep-dive + cross-check with the
Android for Cars App Library documentation. Bumping to a new
minor version because this is a behavioural shift, not just
another patch.

## 🐛 Fixed

### Autogram still not appearing on the car screen (MESSAGING-vs-NAVIGATION category hijack)

Since v1.18.1 the `CarAppService` in the manifest had been
declaring **three** Gearhead categories simultaneously:

```xml
<intent-filter>
    <action android:name="androidx.car.app.CarAppService" />
    <category android:name="androidx.car.app.category.MESSAGING" />
</intent-filter>
<intent-filter>
    <action android:name="androidx.car.app.CarAppService" />
    <category android:name="androidx.car.app.category.IOT" />
</intent-filter>
<intent-filter>
    <action android:name="androidx.car.app.CarAppService" />
    <category android:name="androidx.car.app.category.NAVIGATION" />
</intent-filter>
```

Per Google's docs, a CarAppService is expected to declare
**exactly one** primary category, and that category dictates
*both* where the app appears in the Android Auto launcher *and*
which templates it's allowed to return. Co-declaring `MESSAGING`
alongside `NAVIGATION` isn't a supported combo (only
MESSAGING + CALLING is). Gearhead classified Autogram as a
messaging app → it didn't appear under Navigation in the
launcher, and tapping it landed the user on Android Auto's
built-in empty-messaging surface (the dreaded **"No se han
recibido mensajes mientras se conducía"**) instead of our
`NavigationTemplate` + `SurfaceCallback`-rendered home. The
surface our code was drawing was never requested — AA was
waiting for a `ConversationItem`-shaped messaging template and
silently dropping our NavigationTemplate response.

Fixed by keeping **only** `androidx.car.app.category.NAVIGATION`
on the service. The app now appears correctly in the Android
Auto Navigation launcher and taps through to our custom canvas
(big Merlin circle, shortcut chips, secondary row).

**Listen/Reply actions on incoming voice notifications still
work.** Those are posted via `NotificationCompat.MessagingStyle`
+ `CarAppExtender`, a per-notification mechanism that Gearhead
evaluates independently of the CarAppService's declared
category. The `uses name="notification"` line in
`automotive_app_desc.xml` is the only piece that matters for
notification routing, and it's unchanged.

Verified against: developer.android.com/training/cars/apps/navigation,
developer.android.com/training/cars/communication/templated-messaging,
and the androidx.car.app API reference.

### Audio not audible when connected to Android Auto over USB

User report: phone connected to car via USB (AA active). Tap
"Play last original" on the phone screen. Music ducks (confirms
our audio focus request fired) but no voice plays audibly. Same
button works fine once the phone is disconnected from the car.

Root cause in `AudioPlayer.preferBluetoothRoute`. The MediaPlayer
was being told to route to `AudioDeviceInfo.TYPE_BLUETOOTH_A2DP`
whenever any A2DP device was **available**. On a USB-AA session
the car is usually still paired over BT — so A2DP shows up as
available even though the active media route is the
USB/BUS-backed AA channel. `setPreferredDevice(BT_A2DP)` forces
MediaPlayer to write to a BT sink the car isn't monitoring →
bytes go nowhere the user can hear.

Fixed by gating the preference: if the audio-output device list
includes any car-path type (`TYPE_BUS`, `TYPE_USB_ACCESSORY`,
`TYPE_USB_DEVICE`, `TYPE_USB_HEADSET`, `TYPE_HDMI`), skip
`setPreferredDevice` entirely and let the OS hand the stream to
whatever channel AA is actually playing through. When the phone
*isn't* connected to a car — plain BT headset, wired
headphones, wireless AA over BT — the original priority chain
(A2DP → wired → SCO) still applies so the user doesn't
accidentally get pushed to the phone speaker.

## Install

Update from 1.19.12. Reconnect to the car: Autogram should now
appear in Android Auto's **Navigation** section (where Waze /
Google Maps live). Tap it to land on the custom home screen with
Merlin and the shortcut chips. Playing the last original from
the phone while connected to the car should now be audible
through the car speakers.

If the tile is still missing, double-check:

1. **Unknown sources** is enabled in Android Auto → Developer
   Settings on the phone (tap the AA version number ten times
   to unlock the dev menu).
2. **Android Auto app** on the phone is up to date (Play Store).
3. The app was cold-launched at least once after updating so the
   new manifest took effect (Gearhead caches the CarAppService
   registration between boots).
