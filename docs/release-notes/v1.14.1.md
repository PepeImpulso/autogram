# v1.14.1 — Visibilidad en Android Auto + auto-play en el coche 🚗🔧

Dos bugs que el usuario encontró probando Autogram en el coche.

## 🐛 Fixed

- **La app no aparecía en el launcher de Android Auto.** El
  `CarAppService` declaraba solo la categoría `IOT` con
  `minCarApiLevel=1`. Los hosts de AA recientes (14+) esconden las
  apps sideloaded IOT-only con level 1, y faltaba enteramente el
  hook `MESSAGING` que ruta las notificaciones de mensaje entrantes
  por el coche.
  - Bump de `androidx.car.app.minCarApiLevel` a **3** (mínimo
    recomendado actual para apps visibles en launcher).
  - Segundo `intent-filter` con `androidx.car.app.category.MESSAGING`
    junto al `IOT` existente — AA matchea cualquiera de los dos,
    así que ahora la app aparece en el launcher **Y** es un target
    válido para notificaciones messaging.
  - `android:appCategory="social"` en la `<application>` tag para
    que el categorizador de AA la coloque junto a otras apps
    sociales/mensajería.

  Caveat: APKs sideloaded siguen requiriendo que el usuario active
  "Unknown sources" dentro de Android Auto → Developer settings en
  el móvil. Es config one-time del host, no lo podemos empaquetar.

- **Auto-play denegado por audio focus.** Sentry reportó
  "Audio focus denegado" en v1.13.0+35 en el S936B del usuario —
  exactamente el path de fallo cuando AA / Google Maps ya tiene
  foco. El código antiguo hard-fallaba:

  ```kotlin
  if (!requestAudioFocus()) {
      Timber.w("Audio focus denegado")
      return Result.failure(...)
  }
  ```

  Eso marcaba el mensaje como FAILED y nunca se reproducía — por
  eso en el coche solo veías saltar la notificación.

  Fix en `AudioPlayer`:
  - Cambiado el request a **`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`**.
    El hint "may duck" permite que los prompts de navegación sigan
    sonando a volumen reducido en vez de tener que pausarse, y AA
    lo concede libremente donde deniega el full-transient.
  - `setWillPauseWhenDucked(false)` para que nuestro propio
    playback siga durante ventanas de ducking.
  - Aunque el foco sea denegado, ahora llamamos a
    `MediaPlayer.start()` igualmente — Android mezcla a volumen
    reducido via la capa de ducking de la plataforma, que es
    estrictamente mejor que el fallo silencioso.

- `MtprotoReceiverService.handleVoiceNote` añade un `Timber.i()`
  que resume el estado de decisión (autoPlay, silent, inCall,
  summarize, engine) para cada entrante — así la próxima vez que
  un mensaje no auto-reproduzca se ve en logcat/breadcrumbs
  Sentry qué rama se tomó, en vez de adivinar.

## Install

Actualización desde 1.14.0. Tras instalar, toca **Forzar detención**
de Android Auto en Ajustes del móvil para que re-escanee apps — la
próxima vez que abras AA, Autogram aparece en el launcher.
