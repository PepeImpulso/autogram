# v1.14.1 — Android Auto visibility + auto-play in the car 🚗🔧

Two bugs the user found while testing Autogram in the car.

## 🐛 Fixed

- **The app didn't appear in the Android Auto launcher.** The
  `CarAppService` declared only the `IOT` category with
  `minCarApiLevel=1`. Recent AA hosts (14+) hide sideloaded
  IOT-only apps with level 1, and the `MESSAGING` hook that
  routes incoming-message notifications through the car was
  missing entirely.
  - Bump `androidx.car.app.minCarApiLevel` to **3** (the
    current minimum recommended for apps visible in the
    launcher).
  - A second `intent-filter` with
    `androidx.car.app.category.MESSAGING` alongside the
    existing `IOT` — AA matches either, so now the app appears
    in the launcher **AND** is a valid target for messaging
    notifications.
  - `android:appCategory="social"` on the `<application>` tag
    so the AA categorizer places it next to other
    social/messaging apps.

  Caveat: sideloaded APKs still require the user to enable
  "Unknown sources" inside Android Auto → Developer settings on
  the phone. It's a one-time host config, we can't bundle it.

- **Auto-play denied by audio focus.** Sentry reported "Audio
  focus denied" on v1.13.0+35 on the user's S936B — exactly
  the failure path when AA / Google Maps already holds focus.
  The old code hard-failed:

  ```kotlin
  if (!requestAudioFocus()) {
      Timber.w("Audio focus denegado")
      return Result.failure(...)
  }
  ```

  That marked the message as FAILED and it never played — that's
  why in the car you only saw the notification pop up.

  Fix in `AudioPlayer`:
  - Changed the request to
    **`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`**. The "may duck"
    hint lets navigation prompts keep playing at reduced volume
    instead of having to pause, and AA grants it liberally where
    it denies full-transient.
  - `setWillPauseWhenDucked(false)` so our own playback
    continues during ducking windows.
  - Even if focus is denied, we now call `MediaPlayer.start()`
    anyway — Android mixes at reduced volume via the platform's
    ducking layer, which is strictly better than silent failure.

- `MtprotoReceiverService.handleVoiceNote` adds a `Timber.i()`
  that summarizes the decision state (autoPlay, silent, inCall,
  summarize, engine) for each incoming — so next time a message
  doesn't auto-play we can see in logcat/Sentry breadcrumbs
  which branch was taken, instead of guessing.

## Install

Update from 1.14.0. After installing, tap **Force stop** on
Android Auto in the phone's Settings so it rescans apps — next
time you open AA, Autogram appears in the launcher.
