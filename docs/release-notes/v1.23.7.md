# v1.23.7 — Pending Queue list now shows every deferred message 📋⏭️

Two runtime bugs surfaced while exercising v1.23.6 on-device.

## 🐛 Fixed

- **Pending Queue tab · the list now shows every pending message, not just
  the one playing.** The home-screen badge counted busy-deferred messages
  but the list inside the Pending tab was empty whenever those messages
  hadn't been promoted by `enqueuePending`. Three call sites in
  `PlayReplyUseCase` (`playVoiceMessage`, `playTextMessage`,
  `playSummaryOrTranscription`) were doing a bare `pendingQueue.add(...)`
  when the busy-check fired, which kept the message in memory but never
  flipped its `state` to `PENDING_PLAYBACK` or inserted a row into
  `pending_playbacks`. The Pending tab's `observePendingPlaybackQueue`
  query filters by `state = 'PENDING_PLAYBACK'` — so deferred messages
  were invisible there. Routed all three through `enqueuePending` with a
  new `PendingReason.PLAYBACK_BUSY`; the list now reflects the same set
  the count badge advertises. The bug pre-dated v1.23.6 for text + summary
  paths; v1.23.4 inadvertently extended it to voice when the busy-check
  was added there for symmetry with TTS.

- **Android Auto · skip-previous now walks message history instead of
  restarting current.** v1.23.6 added a true previous-message control to
  the phone's Now Playing panel but forgot to re-wire the
  `MediaSessionCompat` callback at `PlayReplyUseCase:85`, so the
  lock-screen / car / Bluetooth headset's skip-prev still mapped to
  `restartCurrent()`. Fixed: `onSkipToPrevious` now calls `skipPrevious()`
  when there's history to walk back through, falling back to
  `restartCurrent()` when history is empty so the control still does
  *something* useful even on a fresh session.
