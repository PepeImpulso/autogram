# v1.22.4 — Pulsing ring on the speaking circle + AA voice search 🎙️

After Pepe asked "while a message is playing, can the contact circle on
the screen be highlighted? — that way I'll know who's speaking and can
reply right after," this release adds that visual cue and bundles three
fixes for AA / Bluetooth-headset capabilities that surfaced from a 9th
bug-hunt round on the v1.22.x media work.

## ✨ Added

- **Home · Pulsing gold ring while playback is active.** The contact
  circle for the conversation whose message is currently being read
  aloud now gets an animated gold ring (alpha + width breathe over
  900 ms). Lets you identify the speaker at a glance — important when
  audio routes to the car speakers and the phone screen is glanceable
  rather than focused. Driven by a new
  `MainViewModel.currentlyPlayingConversationId` StateFlow that resolves
  the playing message's conversationId via Room, so the ring tracks the
  active circle (primary or secondary) regardless of which
  conversation is speaking. Disappears the moment playback stops.

- **AA / Assistant · Voice search support.** "Hey Google, play X on
  Autogram" now reaches the app. Three pieces wired together:
    1. New `MEDIA_PLAY_FROM_SEARCH` intent-filter on `MainActivity` so
       AA / Assistant can dispatch the launch intent.
    2. New `onPlayFromSearch(query)` override on the
       `MediaSessionCompat.Callback` so AA's voice query reaches our
       playback logic via the controller-binder path.
    3. Implementation in `PlayReplyUseCase`: empty query falls through
       to draining pending; non-empty query is matched
       case-insensitively against pinned conversation titles and the
       most recent message in the first matching conversation is
       played. No match → drain pending so the user always hears
       something rather than silence.

- **Bluetooth headset · Hardware media-button routing.** Declared
  `androidx.media.session.MediaButtonReceiver` in the manifest so
  pause/play/skip from a paired Bluetooth headset (or wired-headset
  remote) routes to the topmost active MediaSession — Autogram, while
  it's speaking. Pre-v1.22.4 the system warned
  `MediaSessionCompat: Couldn't find a unique registered media button
  receiver` and headset transport buttons silently no-op'd against
  Autogram. AA's controller path was unaffected — this fixes the
  out-of-AA case.

## 🐛 Fixed

- Cleared two new lint errors (`MissingIntentFilterForMediaSearch`,
  `MissingOnPlayFromSearch`) that turned `lintDebug` red. Both came
  from the AA voice search work — once the intent-filter and the
  callback override were added, lint passes cleanly.

## 🧪 Tests + verification

- `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug`
  all green.
- `:app:assembleRelease` (R8) succeeds; ProGuard mapping confirms
  `MediaSessionCompat.Callback` subclass methods, `MediaButtonReceiver`,
  and `AutogramMediaBrowserService` survive minification.
- Verified end-to-end on the Android 15 emulator (`autogram-test` AVD,
  v1.22.3 → v1.22.4 update via `install -r`) that:
    - MediaSession transitions PLAYING → STOPPED on incoming text TTS.
    - Tap-to-replay from History flips the session to PLAYING with
      the right message metadata.
    - In-app pause flips it to `PAUSED, speed=0.0` — the ring fades
      out (only Playing triggers it), session metadata preserved.
    - Resume restores `PLAYING, speed=1.0`.
