# v1.23.0-rc.7 — Inline waveform on the active row 🎚️

Builds directly on rc.6's tap-to-seek work. The waveform that until now
only lived inside the Pending Queue's *Now Playing* panel now also
appears underneath the active row in **History** and **Pending Queue**,
so the user can scrub a message in place without opening a separate
*Now Playing* surface.

## ✨ Added

- **History + Pending row · Inline waveform with tap + drag-to-seek.**
  When a row is the active playback target *and* has an audio file,
  a 28 dp waveform renders below the row contents. Tap any point on it
  to jump playback there; drag horizontally to scrub. Same gesture
  contract as the Pending Queue's *Now Playing* waveform — both call
  `PlayReplyUseCase.seekTo()` (already in place since rc.6) and update
  the local position state immediately so the bar doesn't briefly snap
  back to the old value before the 250 ms poller catches up to the
  seek. Text-only rows (TTS playback) don't render the waveform —
  there's nothing useful to draw and nothing to seek into.

## 🔍 Changed

- **Row layout · Live `0:15 / 1:30` readout moved next to the arrival
  time.** Pre-rc.7 the readout sat under the subtitle, but a 2-line
  subtitle pushed it out of view because the row's right column (with
  the play button) was what dictated the row height. Co-locating both
  clock-style readouts (arrival time + elapsed/total) inside the
  trailing column keeps them visually grouped and out of the
  subtitle's wrap area. The `0:15 / 1:30` text itself is unchanged —
  same theme-primary color, same ~250 ms poll cadence, same
  pause-stops-the-poll behaviour from rc.6.

- **`MessageRow` polling state hoisted.** `positionMs` / `durationMs`
  live above the inner `Row` now so both the trailing time column and
  the inline waveform read the same numbers each frame. Single
  `LaunchedEffect` per active row instead of one per readout.
