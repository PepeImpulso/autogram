# v1.11.0 — Automatic summary of long messages (M4 #4) 📝

Item #4 of the roadmap. When an incoming message (text or
voice transcription) exceeds 60 words, we produce a 1-2
sentence summary using the user's preferred engine.

## ✨ Added — two engines, same interface

**1. Gemini Nano (on-device)** — loads the Google AI Edge
`aicore` runtime via Kotlin reflection. No compile-time
dependency, so the app works on devices without aicore
(fallback `NotAvailable`). When Samsung/Pixel ship the runtime
as a system service (S24+/S25+/Pixel 8+), the integration
activates itself without code changes.

**2. LLM endpoint (configurable)** — any OpenAI-compatible
endpoint: OpenAI, Anthropic shim, Ollama, Groq, LM Studio,
LocalAI, etc. The user configures URL + API key + model in
Settings → Summary. We only speak `/chat/completions` with
system + user; temperature 0.2, max_tokens 160. Endpoint and
key **never go into logs** (Sentry scrubbing has been in place
since v1.8.1).

## Orchestration

- `SummarizeMessageUseCase` enforces idempotence + word
  threshold.
- Chained from `TranscribeVoiceUseCase.Success`
  (post-transcribe) and from
  `MtprotoReceiverService.handleText` for direct text messages.
- State written to `Message.summaryState`: NONE → PENDING →
  IN_PROGRESS → DONE/FAILED/UNAVAILABLE.

## 🔍 Changed

- Migration v11→v12: 2 new columns in `messages` (text + state)
  and 5 in `settings` (toggle, engine, endpoint, apiKey,
  model).
- UI: `HistoryScreen` shows the summary as a highlighted block
  above the transcription with a progress indicator while it's
  computed.
- Settings → Summary: engine radio group, conditional fields
  for the endpoint. `DebouncedTextField` commits to DB 500ms
  after the last keystroke — no per-character writes.

## Install

Update from 1.10.x. By default summary is OFF — you enable it
in Settings once you've configured the engine.
