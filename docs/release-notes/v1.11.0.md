# v1.11.0 — Resumen automático de mensajes largos (M4 #4) 📝

Item #4 del roadmap. Cuando un mensaje entrante (texto o
transcripción de voz) supera las 60 palabras, producimos un resumen
de 1-2 frases con el motor que el usuario prefiera.

## ✨ Added — dos motores, misma interface

**1. Gemini Nano (on-device)** — carga el runtime `aicore` de Google
AI Edge via reflection de Kotlin. Sin dependencia en tiempo de
compilación, así que la app funciona en dispositivos sin aicore
(fallback `NotAvailable`). Cuando Samsung/Pixel distribuyan el
runtime como servicio del sistema (S24+/S25+/Pixel 8+), la
integración se activa sola sin cambio de código.

**2. Endpoint LLM (configurable)** — cualquier endpoint compatible
con OpenAI: OpenAI, shim de Anthropic, Ollama, Groq, LM Studio,
LocalAI, etc. Usuario configura URL + API key + modelo en Ajustes →
Resumen. Hablamos solo `/chat/completions` con system + user;
temperature 0.2, max_tokens 160. Endpoint y key **nunca entran a
logs** (el scrubbing de Sentry ya estaba desde v1.8.1).

## Orquestación

- `SummarizeMessageUseCase` guarda la idempotencia + umbral de
  palabras.
- Encadenado desde `TranscribeVoiceUseCase.Success` (post-transcribe)
  y desde `MtprotoReceiverService.handleText` para mensajes de texto
  directos.
- Estado escrito en `Message.summaryState`: NONE → PENDING →
  IN_PROGRESS → DONE/FAILED/UNAVAILABLE.

## 🔍 Changed

- Migración v11→v12: 2 columnas nuevas en `messages` (texto + estado)
  y 5 en `settings` (toggle, engine, endpoint, apiKey, model).
- UI: `HistoryScreen` muestra el resumen como bloque destacado
  encima de la transcripción con progress indicator mientras se
  computa.
- Ajustes → Resumen: radio group de motor, campos condicionales
  para endpoint. `DebouncedTextField` commitea a DB 500ms después
  de la última tecla — sin escrituras por carácter.

## Install

Actualización desde 1.10.x. Por defecto el resumen está OFF — lo
activas en Ajustes cuando hayas configurado el motor.
