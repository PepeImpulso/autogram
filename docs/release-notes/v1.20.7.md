# v1.20.7 — Spanish text spoken with a Spanish voice

This release fixes the long-standing bug where a reply written in Spanish was
read aloud by the engine's English voice. Detection now catches Spanish even
when the text is accent-less, and the engine is forced onto a voice it
actually has installed instead of silently defaulting to English.

## Fixed

- **Spanish replies no longer read in English voice.** `TtsPlayer.detectLocale`
  used to rely entirely on Spanish-specific characters (ñ, ¿, ¡, accented
  vowels). A reply like "voy en camino" has none of those, so the detector
  fell back to the UI locale and the engine spoke it in English. The detector
  now also scores the text against Spanish vs English stopwords ("voy", "en",
  "como", "es" vs "the", "is", "going", "and") and only declares a winner
  when one side leads by at least two hits — short greetings stay on the UI
  locale, real sentences flip to the right language.
- **Engine no longer silently downgrades to English** when the requested
  voice isn't installed on the device. `TextToSpeech.setLanguage` returns
  `LANG_MISSING_DATA` in that case, and we used to throw the return value
  away. We now check `isLanguageAvailable` first and walk a fallback ladder
  (requested → language-only → UI locale) so a Spanish-language device
  without `es-ES` data still gets the generic Spanish voice instead of an
  English one.
