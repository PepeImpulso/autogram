# v1.19.7 — Shortcut sounds, pill auto-hide, persistent play-last button, CSO record fix, hide/show shortcuts ✨

Six user-requested improvements in one pass, all focused on the
phone home screen and the shortcuts editor.

## ✨ Added

### Shortcut send sounds

Text and voice shortcuts now play a short audio chime when they
reach Telegram (`TONE_PROP_ACK` — two-note rising chirp) and a
distinct error buzzer when the send fails (`TONE_PROP_NACK` —
descending tone). The driver gets audible confirmation without
having to glance at the status pill. Both tones respect the
existing **Recording beep** volume setting — turn it down to 0 %
and all cues (start, end, sent, error) fall silent together.

### Persistent "play last original" button, top-right

Moved the `Play last original` affordance from the body row to
the top-right corner of the hero header, and made it always
visible. When there's no incoming audio to play, the button is
shown in a greyed disabled state; when the last original is
already playing, the icon swaps to `Stop` and a tap stops
playback. If something else is playing (a TTS summary, an old
message) when you tap, it's replaced with the last original
cleanly — no stacked audio.

### Show/hide shortcuts from home

Each shortcut in the editor now has a **Switch** you can flip to
hide it from the home screen without deleting it. Disabled
shortcuts fade to the surface-variant colour in the editor and
keep their label/voice file intact, so re-enabling is a single
tap. Persisted through the existing `QuickReplyEntity.isEnabled`
column (added way back in v1.17's shortcut schema, but never
previously exposed in the UI).

To support this, added a parallel
`QuickReplyDao.observeAllIncludingDisabled()` flow. The home
screen keeps using the original `observeAll()` (filters to
enabled only); the editor uses the new one so the user can see
their hidden shortcuts.

## 🔍 Changed

### Status pill auto-dismisses after 5 s

Terminal statuses (**Sent / Error / Discarded / QueuedOffline**)
now self-clear from the hero pill 5 s after they appear, then
the pill hides entirely — no more persistent "Ready" label
sitting next to the play button forever. Implemented via a
`MutableStateFlow`-scoped delay job in `MainViewModel` that
cancels itself on any new status transition, so a rapid
Sent → Sending → Sent sequence doesn't clobber the final state
early. Mirrored on Android Auto (`MainScreen`) where the same
terminal states also clear after 5 s.

The pill's text is also capped at 160 dp with single-line
ellipsis so a long Telegram error like
`Telegram 400: MESSAGE_ID_INVALID` can't push the new play
button off the right edge of the header on narrow phones.

### "Recording sound" → "Recording beep"

Renamed the settings entry in all six locales and added a
description line explaining **what** the beep is and **when**
it plays. Was previously labelled `Recording sound` in English
and `Sonido al grabar` in Spanish — both ambiguous (sound of
what? the playback? the mic feed?). The new label plus sub-line
("short tone at start/end so you know the mic opened") makes it
obvious.

Extended `SliderRow` with an optional `supporting` parameter
so any future slider can show a similar sub-line; applied it
only to the recording-beep setting for now.

## 🐛 Fixed

### First secondary avatar ("CSO") wouldn't record

The press-and-hold gesture on a 72 dp secondary circle could
resolve as a tap-and-release in under the ~250 ms that
`MediaRecorder.stop()` needs to commit a first frame. The
native call then threw `stop failed`, we caught it as "audio
couldn't be saved", and flashed the Error pill — looked like
"recording starts and stops immediately" to the user.

Added a 350 ms minimum-hold threshold in `RecordCircle`'s
pointer-input gesture: shorter presses now silently cancel the
just-started recording (same path as dragging out of the
circle) instead of trying to send an empty file. 350 ms is well
above a deliberate tap and well below a natural hold, so legit
recordings start and send exactly as before. Applied to both
the 176 dp primary and all 72 dp secondaries via the shared
`RecordCircle` composable.

## 🧪 Internal

- `QuickReplyRepository.observeAllIncludingDisabled()` + DAO
  passthrough. Home flows unchanged.
- `SendVoiceMtprotoUseCase` success/failure branches of
  `sendQuickReply` and `sendVoiceShortcut` now invoke
  `RecordingSounds.playSent()` / `playError()`.
- `MainViewModel.toggleLastOriginal()` — combined play/stop
  entry point for the hero-header button. Calls `stopAll()`
  before `playManually()` so a TTS summary doesn't overlap the
  original.
- Status pill hides completely on Idle when there's no outbox
  count / pending playbacks to surface.
- Build: 37 + 6 user-visible tweaks; nothing changed on the
  wire format, DB schema, or TDLib auth.

## Install

Update from 1.19.6. No migration, no permission changes. First
time you open the Shortcuts editor you'll see the new Switch on
every row — they're all ON by default (the existing behaviour),
flip them off to hide one without deleting it. The "play last
original" button lives in the top-right corner now; the old
body-row version is gone.
